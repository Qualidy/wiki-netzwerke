# 🔍 Tag 9: Vertiefung Wireshark - Paketanalyse für Anfänger



## **📚 Theorie – Wireshark verstehen**

---


### **1. Was ist Wireshark?**

Wireshark ist wie ein **Mikroskop für dein Netzwerk**:

- Es **fängt alle Datenpakete** ein, die durch dein Netzwerk fließen.
- Es zeigt dir **jeden einzelnen Schritt** einer Kommunikation (z. B. HTTP-Anfrage, DNS-Abfrage).
- Es hilft dir, **Probleme zu finden** (z. B. warum eine Webseite nicht lädt).

**Beispiel:**

- Du rufst `google.com` auf → Wireshark zeigt dir:
  1. **DNS-Anfrage** ("Was ist die IP von google.com?").
  2. **TCP-Handshake** (Verbindung aufbauen).
  3. **HTTP-Anfrage** ("Gib mir die Startseite!").
  4. **HTTP-Antwort** (Die Webseite wird zurückgeschickt).

---

---

### **2. Wichtige Begriffe in Wireshark**


| **Begriff**   | **Erklärung**                               | **Beispiel**                      |
| ------------- | ------------------------------------------- | --------------------------------- |
| **Paket**     | Ein kleines Datenstück im Netzwerk.         | Wie ein Brief im Postsystem.      |
| **Protokoll** | Regeln, nach denen Daten übertragen werden. | HTTP, TCP, IP, DNS.               |
| **Quell-IP**  | Die IP-Adresse des Absenders.               | 192.168.1.100                     |
| **Ziel-IP**   | Die IP-Adresse des Empfängers.              | 8.8.8.8                           |
| **Port**      | Eine "Tür" für bestimmte Dienste.           | Port 80 (HTTP), Port 443 (HTTPS). |
| **Filter**    | Zeigt nur bestimmte Pakete an.              | `http`, `ip.addr == 8.8.8.8`.     |


---

---

### **3. Aufbau eines Pakets**

Jedes Paket in Wireshark hat **mehrere Schichten** (wie eine Zwiebel):

1. **Ethernet (Schicht 2)**:
  - **Quell-MAC** und **Ziel-MAC** (Hardware-Adressen).
2. **IP (Schicht 3)**:
  - **Quell-IP** und **Ziel-IP**.
3. **TCP/UDP (Schicht 4)**:
  - **Quell-Port** und **Ziel-Port**.
4. **Anwendung (Schicht 7)**:
  - **Inhalt** (z. B. HTTP-Anfrage, DNS-Abfrage).

**Beispiel (HTTP-Anfrage):**

```
Ethernet: src=00:11:22:33:44:55, dst=aa:bb:cc:dd:ee:ff
IP: src=192.168.1.100, dst=142.250.186.46
TCP: src=54321, dst=80
HTTP: GET / HTTP/1.1
```

---

---

### **4. Farben in Wireshark**

Wireshark farblich markiert Pakete, um sie leichter zu erkennen:


| **Farbe**   | **Bedeutung**       | **Beispiel**                               |
| ----------- | ------------------- | ------------------------------------------ |
| **Blau**    | TCP-Pakete.         | HTTP, FTP.                                 |
| **Grün**    | HTTP-Pakete.        | Webseitenaufrufe.                          |
| **Schwarz** | ICMP-Pakete.        | Ping.                                      |
| **Rot**     | Fehlerhafte Pakete. | Zeitüberschreitung, fehlerhafte TCP-Flags. |
| **Gelb**    | UDP-Pakete.         | DNS, DHCP.                                 |

## **🎮 Praxis – Wireshark installieren und nutzen**

---

---

### **📌 Schritt 1: Wireshark installieren**

```bash
# Wireshark installieren
sudo apt update
sudo apt install wireshark -y

# Wireshark starten (als Root)
sudo wireshark
```

**Hinweis:**

- Wireshark **muss als Root** gestartet werden, um Pakete einzufangen.
- Falls du Wireshark **ohne Root** nutzen willst:
  ```bash
  sudo usermod -aG wireshark $USER
  ```
  → Melde dich ab und wieder an.

---

---

### **📌 Schritt 2: Erste Aufzeichnung starten**

1. **Netzwerkinterface auswählen** (z. B. `eth0`, `wlan0`).
2. Klicke auf den **blauen Hai** (Start), um die Aufzeichnung zu beginnen.
3. **Rufe eine Webseite auf** (z. B. `http://example.com`).
4. Klicke auf das **rote Quadrat** (Stop), um die Aufzeichnung zu beenden.

**Was du siehst:**

- Eine **Liste aller Pakete**, die während der Aufzeichnung empfangen wurden.

---

---

### **📌 Schritt 3: Pakete analysieren**

1. **Klicke auf ein Paket** in der Liste.
2. **Details anzeigen** (mittlerer Bereich):
  - **Ethernet** (MAC-Adressen).
  - **IP** (IP-Adressen).
  - **TCP/UDP** (Ports).
  - **HTTP/DNS/etc.** (Inhalt).
3. **Hex-Dump** (unterer Bereich):
  - Zeigt den **Rohinhalt** des Pakets in Hexadezimal- und ASCII-Format.

---

---

### **📌 Schritt 4: Filter anwenden**


| **Filter**           | **Beschreibung**                 | **Beispiel**         |
| -------------------- | -------------------------------- | -------------------- |
| `http`               | Zeigt nur HTTP-Pakete.           | `http`               |
| `dns`                | Zeigt nur DNS-Pakete.            | `dns`                |
| `tcp`                | Zeigt nur TCP-Pakete.            | `tcp`                |
| `ip.addr == 8.8.8.8` | Zeigt nur Pakete von/to 8.8.8.8. | `ip.addr == 8.8.8.8` |
| `tcp.port == 80`     | Zeigt nur Pakete auf Port 80.    | `tcp.port == 80`     |
| `http.request`       | Zeigt nur HTTP-Anfragen.         | `http.request`       |
| `http.response`      | Zeigt nur HTTP-Antworten.        | `http.response`      |


**Beispiel:**

- Gib `http` in das **Filterfeld** ein → nur HTTP-Pakete werden angezeigt.
- Gib `ip.addr == 8.8.8.8` ein → nur Pakete von/to Google DNS.

---

---

### **📌 Schritt 5: DNS-Anfragen analysieren**

1. Starte eine **neue Aufzeichnung**.
2. Führe einen **Ping** aus:
  ```bash
   ping google.com
  ```
3. Stoppe die Aufzeichnung.
4. Filtere nach **DNS**:
  ```plaintext
   dns
  ```
5. **Analysiere die DNS-Pakete**:
  - **Anfrage:** `Standard query 0x1234 A google.com`
  - **Antwort:** `Standard query response 0x1234 A google.com A 142.250.186.46`

**Was passiert hier?**

1. Dein PC fragt: **"Was ist die IP von google.com?"** (DNS-Anfrage).
2. Der DNS-Server antwortet: **"Die IP ist 142.250.186.46"** (DNS-Antwort).

---

---

### **📌 Schritt 6: TCP-Handshake analysieren**

1. Starte eine **neue Aufzeichnung**.
2. Rufe eine **Webseite** auf (z. B. `http://example.com`).
3. Stoppe die Aufzeichnung.
4. Filtere nach **TCP**:
  ```plaintext
   tcp
  ```
5. **Suche nach dem TCP-Handshake** (drei Pakete):
  - **SYN** (Synchronize) → Verbindung wird initiiert.
  - **SYN-ACK** (Synchronize-Acknowledge) → Server bestätigt.
  - **ACK** (Acknowledge) → Client bestätigt.

**Warum ist das wichtig?**

- Der **TCP-Handshake** stellt sicher, dass die Verbindung **zuverlässig** aufgebaut wird.

---

---

### **📌 Schritt 7: HTTP-Anfragen analysieren**

1. Starte eine **neue Aufzeichnung**.
2. Rufe eine **Webseite** auf (z. B. `http://example.com`).
3. Stoppe die Aufzeichnung.
4. Filtere nach **HTTP**:
  ```plaintext
   http
  ```
5. **Analysiere die HTTP-Pakete**:
  - **GET / HTTP/1.1** → Anfrage an den Server.
  - **Host: example.com** → Die angefragte Webseite.
  - **HTTP/1.1 200 OK** → Antwort des Servers (200 = Erfolg).

**Was bedeutet das?**

- **GET / HTTP/1.1**: Dein Browser fragt die **Startseite** an.
- **200 OK**: Der Server hat die Anfrage **erfolgreich bearbeitet**.

---

---

### **📌 Schritt 8: ICMP (Ping) analysieren**

1. Starte eine **neue Aufzeichnung**.
2. Führe einen **Ping** aus:
  ```bash
   ping 8.8.8.8
  ```
3. Stoppe die Aufzeichnung.
4. Filtere nach **ICMP**:
  ```plaintext
   icmp
  ```
5. **Analysiere die ICMP-Pakete**:
  - **Echo (Ping) request** → Dein PC sendet eine Ping-Anfrage.
  - **Echo (Ping) reply** → Der Server antwortet.

**Was bedeutet das?**

- **ICMP** wird für **Ping** und andere Diagnosezwecke genutzt.

## **🎓 Zusammenfassung – das Wichtigste**


| **Thema**         | **Was es macht**                       | **Beispiel**                     |
| ----------------- | -------------------------------------- | -------------------------------- |
| **Wireshark**     | Fängt und analysiert Netzwerkpakete.   | `sudo wireshark`                 |
| **Paket**         | Ein Datenstück im Netzwerk.            | HTTP-Anfrage, DNS-Antwort.       |
| **Filter**        | Zeigt nur bestimmte Pakete an.         | `http`, `ip.addr == 8.8.8.8`.    |
| **DNS**           | Wandelt Domainnamen in IP-Adressen um. | `google.com` → `142.250.186.46`. |
| **TCP-Handshake** | Baut eine zuverlässige Verbindung auf. | SYN → SYN-ACK → ACK.             |
| **HTTP**          | Protokoll für Webseiten.               | `GET / HTTP/1.1`.                |
| **ICMP**          | Protokoll für Ping und Diagnose.       | Echo Request/Reply.              |


**Merksätze:**

1. **Wireshark = Mikroskop fürs Netzwerk**.
2. **Filter = Suchfunktion für Pakete**.
3. **DNS = Telefonbuch des Internets**.
4. **TCP-Handshake = Verbindung aufbauen (SYN, SYN-ACK, ACK)**.
5. **HTTP 200 = Alles okay, 404 = Seite nicht gefunden**.
