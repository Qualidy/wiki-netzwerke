# 🌐 Tag 3: IP-Adressierung & Subnetting



## **📖 Theorie**



### **1. Einführung in IP-Adressierung**

Eine **IP-Adresse** (Internet Protocol Address) ist eine **eindeutige numerische Adresse**, die jedem Gerät in einem Netzwerk zugewiesen wird, um die **Kommunikation** zu ermöglichen.

#### **Zweck von IP-Adressen**

- **Identifikation:** Eindeutige Kennung eines Geräts im Netzwerk.
- **Lokalisierung:** Bestimmung des **Standorts** eines Geräts (z. B. in einem Subnetz).
- **Routing:** Weiterleitung von Datenpaketen durch das Netzwerk.

---

---

### **2. IPv4 vs. IPv6**


| **Kriterium**       | **IPv4**                        | **IPv6**                                             |
| ------------------- | ------------------------------- | ---------------------------------------------------- |
| **Adresslänge**     | 32 Bit (4 Bytes)                | 128 Bit (16 Bytes)                                   |
| **Anzahl Adressen** | ~4,3 Mrd. (2³²)                 | ~340 Sextillionen (2¹²⁸)                             |
| **Format**          | Dezimal (z. B. `192.168.1.1`)   | Hexadezimal (z. B. `2001:0db8:85a3::8a2e:0370:7334`) |
| **Verwendung**      | Dominierend (90% des Internets) | Zunehmend (z. B. für IoT, Mobilfunk)                 |
| **Vorteile**        | Einfach, weit verbreitet        | Kein NAT nötig, mehr Adressen, bessere Sicherheit    |
| **Nachteile**       | Adressknappheit, NAT nötig      | Komplexere Konfiguration                             |


#### **IPv4-Adressformat**

- **4 Oktette** (jeweils 8 Bit), durch Punkte getrennt.
- **Beispiel:** `192.168.1.1`
    - **Oktett 1:** `192` (Netzwerkanteil)
    - **Oktett 2:** `168` (Netzwerkanteil)
    - **Oktett 3:** `1` (Subnetzanteil)
    - **Oktett 4:** `1` (Hostanteil)

#### **IPv6-Adressformat**

- **8 Blöcke** à 16 Bit, durch Doppelpunkte getrennt.
- **Beispiel:** `2001:0db8:85a3:0000:0000:8a2e:0370:7334`
  - **Verkürzte Schreibweise:**
    - Führende Nullen können weggelassen werden (`2001:db8:85a3:0:0:8a2e:370:7334`).
    - **Doppelte Nullen** können durch `::` ersetzt werden (`2001:db8:85a3::8a2e:370:7334`).

---

---

### **3. IP-Adressklassen (IPv4)**

IPv4-Adressen werden in **5 Klassen** unterteilt, die den **Verwendungszweck** bestimmen.


| **Klasse** | **Bereich**                 | **Erstes Bit** | **Verwendung**                           | **Standard-Subnetzmaske** |
| ---------- | --------------------------- | -------------- | ---------------------------------------- | ------------------------- |
| **A**      | 1.0.0.0 – 126.255.255.255   | 0              | Große Netzwerke (z. B. Regierungen)      | 255.0.0.0 (/8)            |
| **B**      | 128.0.0.0 – 191.255.255.255 | 10             | Mittlere Netzwerke (z. B. Universitäten) | 255.255.0.0 (/16)         |
| **C**      | 192.0.0.0 – 223.255.255.255 | 110            | Kleine Netzwerke (z. B. Unternehmen)     | 255.255.255.0 (/24)       |
| **D**      | 224.0.0.0 – 239.255.255.255 | 1110           | **Multicast** (Gruppenkommunikation)     | –                         |
| **E/R**      | 240.0.0.0 – 255.255.255.255 | 11110           | Reserved (für zukünftige Verwendung)    | –                         |





#### **Spezielle IP-Adressen**


| **Adresse**       | **Bedeutung**                                                         |
| ----------------- | --------------------------------------------------------------------- |
| `0.0.0.0`         | **Standard-Route** (Default Gateway)                                  |
| `127.0.0.1`       | **Loopback** (lokaler Host)                                           |
| `255.255.255.255` | **Broadcast** (alle Geräte im Netzwerk)                               |
| `169.254.x.x`     | **APIPA** (Automatische private IP-Zuweisung, falls DHCP fehlschlägt) |

### **4. Subnetting – Warum und wie?**

**Subnetting** ist die **Aufteilung eines Netzwerks in kleinere Teilnetze (Subnetze)**, um:

- **IP-Adressen effizienter zu nutzen** (Vermeidung von Adressverschwendung).
- **Netzwerkverkehr zu reduzieren** (geringere Broadcast-Domänen).
- **Sicherheit zu erhöhen** (Isolation von Netzwerksegmenten).
- **Routing zu vereinfachen** (bessere Kontrolle über Datenflüsse).

#### **Subnetzmaske**

- Die **Subnetzmaske** bestimmt, welcher Teil der IP-Adresse zum **Netzwerk** und welcher zum **Host** gehört.
- **Beispiel:**
    - IP: `192.168.1.10`
    - Subnetzmaske: `255.255.255.0` (`/24`)
    - **Netzwerkanteil:** `192.168.1`
    - **Hostanteil:** `.10`

#### **CIDR-Notation (Classless Inter-Domain Routing)**

- **Ersetzt die klassische Klassenunterteilung** (A, B, C).
- **Format:** `IP-Adresse/Präfixlänge` (z. B. `192.168.1.0/24`).
- **Präfixlänge:** Anzahl der Bits für den **Netzwerkanteil** (z. B. `/24` = 24 Bits für Netzwerk, 8 Bits für Hosts).


| **Subnetzmaske** | **CIDR-Notation** | **Anzahl Hosts** |
| ---------------- | ----------------- | ---------------- |
| 255.0.0.0        | /8                | 16.777.214       |
| 255.255.0.0      | /16               | 65.534           |
| 255.255.255.0    | /24               | 254              |
| 255.255.255.128  | /25               | 126              |
| 255.255.255.192  | /26               | 62               |
| 255.255.255.224  | /27               | 30               |
| 255.255.255.240  | /28               | 14               |


#### **Berechnung der Anzahl Hosts pro Subnetz**

- **Formel:** `2^(Anzahl Host-Bits) - 2`
    - **-2**, weil **Netzwerkadresse** und **Broadcast-Adresse** nicht für Hosts genutzt werden können.
- **Beispiel für /24:**
    - Host-Bits: `32 - 24 = 8`
    - Anzahl Hosts: `2^8 - 2 = 256 - 2 = 254`

---

---

### **5. Subnetting Schritt für Schritt**

#### **Beispiel: Netzwerk `192.168.1.0/24` in 4 Subnetze aufteilen**

1. **Anforderung:**
    - 4 Subnetze mit je **mindestens 30 Hosts**.
2. **Host-Bits berechnen:**
    - 30 Hosts → `2^n - 2 ≥ 30` → `n = 5` (2⁵ - 2 = 30).
3. **Netzwerk-Bits:**
    - Ursprünglich: `/24` (24 Bits für Netzwerk).
    - Neue Präfixlänge: `32 - 5 = 27` → **/27**.
4. **Subnetzmaske:**
    - `/27` → `255.255.255.224`.
5. **Subnetze berechnen:**
    - **Subnetz 1:** `192.168.1.0/27` (Hosts: `192.168.1.1` – `192.168.1.30`)
    - **Subnetz 2:** `192.168.1.32/27` (Hosts: `192.168.1.33` – `192.168.1.62`)
    - **Subnetz 3:** `192.168.1.64/27` (Hosts: `192.168.1.65` – `192.168.1.94`)
    - **Subnetz 4:** `192.168.1.96/27` (Hosts: `192.168.1.97` – `192.168.1.126`)

#### **Visualisierung**


| **Subnetz** | **Netzwerkadresse** | **Erste Host-IP** | **Letzte Host-IP** | **Broadcast-Adresse** |
| ----------- | ------------------- | ----------------- | ------------------ | --------------------- |
| Subnetz 1   | 192.168.1.0/27      | 192.168.1.1       | 192.168.1.30       | 192.168.1.31          |
| Subnetz 2   | 192.168.1.32/27     | 192.168.1.33      | 192.168.1.62       | 192.168.1.63          |
| Subnetz 3   | 192.168.1.64/27     | 192.168.1.65      | 192.168.1.94       | 192.168.1.95          |
| Subnetz 4   | 192.168.1.96/27     | 192.168.1.97      | 192.168.1.126      | 192.168.1.127         |

### **6. VLSM (Variable Length Subnet Masking)**

- **Problem:** Bei klassischem Subnetting werden **alle Subnetze gleich groß** erstellt (z. B. 4x /27).
- **Lösung:** **VLSM** ermöglicht **unterschiedlich große Subnetze** innerhalb eines Netzwerks.
- **Beispiel:**
    - Netzwerk: `192.168.1.0/24`
    - **Subnetz 1:** 50 Hosts → `/26` (62 Hosts)
    - **Subnetz 2:** 20 Hosts → `/27` (30 Hosts)
    - **Subnetz 3:** 10 Hosts → `/28` (14 Hosts)

#### **VLSM-Berechnung**

1. **Größtes Subnetz zuerst** (Top-Down-Ansatz).
2. **Subnetz 1 (50 Hosts):**
    - `/26` → `192.168.1.0/26` (Hosts: `192.168.1.1` – `192.168.1.62`).
3. **Subnetz 2 (20 Hosts):**
    - `/27` → `192.168.1.64/27` (Hosts: `192.168.1.65` – `192.168.1.94`).
4. **Subnetz 3 (10 Hosts):**
    - `/28` → `192.168.1.96/28` (Hosts: `192.168.1.97` – `192.168.1.110`).

# 🏗️ Labor: VLANs mit Linux-Bridge und VMs


---
## 📚 **Theorie: VLANs und Linux-Bridges**

---
### **1. Was sind VLANs?**
**VLAN (Virtual Local Area Network)** = Logische Aufteilung eines **physikalischen Netzwerks** in mehrere **virtuelle Teilnetze**.
- **Zweck:**
  - **Isolation:** Trennung von Netzwerksegmenten (z. B. Abteilungen, Sicherheitszonen).
  - **Sicherheit:** Verhindert unerlaubten Datenverkehr zwischen Segmenten.
  - **Performance:** Reduziert Broadcast-Domänen.
  - **Flexibilität:** Geräte können **unabhängig vom physikalischen Standort** einem VLAN zugewiesen werden.

**Beispiel:**
- **VLAN 10:** Sicherheitszone 1 (nur VM 2)
- **VLAN 20:** Sicherheitszone 2 (VM 3 und VM 4)
- **Router-VM:** Verbindet die VLANs und filtert den Verkehr.

---
### **2. Warum eine Linux-Bridge?**
Eine **Linux-Bridge** funktioniert wie ein **virtueller Switch**:
- **Vorteile:**
  - **VLAN-fähig:** Kann **802.1Q-Tagging** (VLAN-ID in Paket-Headern) verarbeiten.
  - **Flexibel:** Ermöglicht die **Trennung von VMs** auf einem einzigen Host.
  - **Kostenlos:** Keine zusätzliche Hardware nötig (nur Software auf dem Host).
- **Nachteil:**
  - **Performance:** Etwas langsamer als physische Switches (aber für Schulungen ausreichend).

---
### **3. VLAN-Tagging (802.1Q)**
- **Tag:** Jedes Paket erhält einen **4-Byte-VLAN-Header** mit der **VLAN-ID (VID)**.
- **PVID (Port VLAN ID):** Standard-VLAN für **untagged Pakete** (Pakete ohne VLAN-Tag).
- **Beispiel:**
  - Ein Paket von **VM 2 (VLAN 10)** wird mit **VID=10** getaggt.
  - Ein Paket von **VM 3 (VLAN 20)** wird mit **VID=20** getaggt.

---
### **4. Netzwerk-Bauplan für das Labor**

## 🛠️ **Praxis: Schritt-für-Schritt-Anleitung**

---

### **📌 Vorbereitung: VMs erstellen**
**Voraussetzung:**
- **4 Ubuntu Server-VMs** (oder andere Linux-Distributionen) auf deinem Host-System (z. B. VirtualBox, VMware, UTM, Proxmox).
- **Netzwerkmodus:** Alle VMs verwenden **Host-Only-Netzwerk** oder **Internes Netzwerk** (je nach Hypervisor).

**Empfohlene VM-Konfiguration:**
| **VM** | **Name** | **RAM** | **CPU** | **Festplatte** | **Netzwerk-Interface** |
|--------|----------|---------|---------|----------------|-----------------------|
| Router | Router-VM | 2 GB | 2 Kerne | 20 GB | eth0 (für Bridge) |
| Client 1 | VM2 | 1 GB | 1 Kern | 10 GB | eth0 (VLAN 10) |
| Client 2 | VM3 | 1 GB | 1 Kern | 10 GB | eth0 (VLAN 20) |
| Client 3 | VM4 | 1 GB | 1 Kern | 10 GB | eth0 (VLAN 20) |

---
---
### **📌 Schritt 1: VLAN-fähige Bridge auf dem Linux-Host einrichten**
**Hinweis:** Falls du **Proxmox** nutzt, kannst du die Bridge direkt im Webinterface erstellen (Haken bei **"VLAN aware"** setzen).
Für **Ubuntu/Debian** (mit `netplan` oder `iproute2`):

#### **Option A: Mit `iproute2` (manuell, für Testzwecke)**
```bash
# 1. Bridge erstellen
sudo ip link add dev br0 type bridge

# 2. VLAN-Filtering aktivieren (WICHTIG!)
sudo ip link set dev br0 type bridge vlan_filtering 1

# 3. Bridge aktivieren
sudo ip link set dev br0 up

# 4. Prüfen, ob die Bridge existiert
ip link show br0
```
**Erwartete Ausgabe:**
```
3: br0: <BROADCAST,MULTICAST,UP,LOWER_UP> mtu 1500 qdisc noqueue state UP mode DEFAULT group default qlen 1000
    link/ether 00:00:00:00:00:00 brd ff:ff:ff:ff:ff:ff
```

#### **Option B: Mit `netplan` (dauerhaft)**
1. Bearbeite die Netplan-Konfiguration:
   ```bash
   sudo nano /etc/netplan/01-netcfg.yaml
   ```
2. Füge folgende Konfiguration hinzu (ersetze `eth0` mit deinem physikalischen Interface, falls nötig):
   ```yaml
   network:
     version: 2
     renderer: networkd
     ethernets:
       eth0:
         dhcp4: no
     bridges:
       br0:
         interfaces: [eth0]
         parameters:
           vlan_filtering: true
         dhcp4: no
   ```
3. Wende die Konfiguration an:
   ```bash
   sudo netplan apply
   ```

---
### **📌 Schritt 2: VMs den VLANs zuweisen**
**Hinweis:** Falls du **Proxmox/UTM/Hyper-V** nutzt, kannst du die VLAN-ID direkt in den VM-Einstellungen eintragen.
Für **manuelle Einrichtung mit `iproute2`** (auf dem Host):

#### **1. Netzwerkinterfaces der VMs zur Bridge hinzufügen**
- **Annahme:** Die VMs sind über **TAP-Interfaces** (z. B. `tap0`, `tap1`, `tap2`, `tap3`) mit dem Host verbunden.
  Falls nicht, erstelle TAP-Interfaces für jede VM:
  ```bash
  sudo ip tuntap add dev tap0 mode tap
  sudo ip tuntap add dev tap1 mode tap
  sudo ip tuntap add dev tap2 mode tap
  sudo ip tuntap add dev tap3 mode tap
  sudo ip link set tap0 up
  sudo ip link set tap1 up
  sudo ip link set tap2 up
  sudo ip link set tap3 up
  ```

#### **2. TAP-Interfaces der Bridge zuweisen und VLANs konfigurieren**
```bash
# Router-VM (tap0): Erhält getaggte Pakete für VLAN 10 und 20
sudo bridge vlan add dev tap0 vid 10
sudo bridge vlan add dev tap0 vid 20

# VM2 (tap1): VLAN 10 (PVID = 10, untagged)
sudo bridge vlan add dev tap1 vid 10 pvid untagged

# VM3 (tap2): VLAN 20 (PVID = 20, untagged)
sudo bridge vlan add dev tap2 vid 20 pvid untagged

# VM4 (tap3): VLAN 20 (PVID = 20, untagged)
sudo bridge vlan add dev tap3 vid 20 pvid untagged
```

#### **3. TAP-Interfaces zur Bridge hinzufügen**
```bash
sudo bridge link add dev tap0
sudo bridge link add dev tap1
sudo bridge link add dev tap2
sudo bridge link add dev tap3
```

#### **4. Prüfen, ob die VLANs korrekt konfiguriert sind**
```bash
bridge vlan show
```
**Erwartete Ausgabe (Ausschnitt):**
```
port    vlan-id
tap0    10
         20
tap1    10 PVID Egress Untagged
tap2    20 PVID Egress Untagged
tap3    20 PVID Egress Untagged
br0     1
```

### **📌 Schritt 3: Router-VM konfigurieren**
Die Router-VM muss die **getaggten Pakete** aus den VLANs verarbeiten.
Dafür richten wir **VLAN-Subinterfaces** ein.

#### **1. VLAN-Subinterfaces in der Router-VM erstellen**
Bearbeite die Netplan-Konfiguration der Router-VM:
```bash
sudo nano /etc/netplan/01-netcfg.yaml
```
Füge folgende Konfiguration ein (ersetze `eth0` mit dem Interface deiner Router-VM):
```yaml
network:
  version: 2
  renderer: networkd
  ethernets:
    eth0:
      dhcp4: no
  vlans:
    eth0.10:          # VLAN 10
      id: 10
      link: eth0
      addresses: [192.168.10.1/24]
    eth0.20:          # VLAN 20
      id: 20
      link: eth0
      addresses: [192.168.20.1/24]
```
Speichern und anwenden:
```bash
sudo netplan apply
```

#### **2. IP-Forwarding aktivieren**
```bash
sudo sysctl -w net.ipv4.ip_forward=1
echo "net.ipv4.ip_forward=1" | sudo tee -a /etc/sysctl.conf
sudo sysctl -p
```

#### **3. Prüfen, ob die VLAN-Interfaces existieren**
```bash
ip a
```
**Erwartete Ausgabe:**

### **📌 Schritt 5: Firewall-Regeln auf der Router-VM einrichten**
Standardmäßig leitet die Router-VM **allen Verkehr zwischen den VLANs weiter**.
Um die VLANs zu **isolieren**, fügen wir Firewall-Regeln hinzu.

#### **1. Alle Verbindungen zwischen VLAN 10 und VLAN 20 blockieren**
```bash
# Blockiere Verkehr von VLAN 20 zu VLAN 10
sudo iptables -A FORWARD -i eth0.20 -o eth0.10 -j DROP

# Blockiere Verkehr von VLAN 10 zu VLAN 20
sudo iptables -A FORWARD -i eth0.10 -o eth0.20 -j DROP
```

#### **2. Erlaube nur bestimmte Verbindungen (optional)**
Falls z. B. **VM3 (VLAN 20)** auf den **Webserver in VLAN 10** zugreifen darf:
```bash
# Erlaube HTTP (Port 80) von VLAN 20 zu VLAN 10
sudo iptables -A FORWARD -i eth0.20 -o eth0.10 -p tcp --dport 80 -j ACCEPT
```

#### **3. Regeln speichern (für Ubuntu/Debian)**
```bash
sudo apt install iptables-persistent -y
sudo netfilter-persistent save
```

### **📌 Typische Fehler & Lösungen**

| **Problem** | **Ursache** | **Lösung** |
|-------------|------------|------------|
| **VLANs funktionieren nicht** | VLAN-Filtering auf der Bridge ist deaktiviert. | `sudo ip link set dev br0 type bridge vlan_filtering 1` |
| **VMs können sich nicht verbinden** | Falsche VLAN-ID oder PVID. | Prüfe mit `bridge vlan show`. |
| **Router leitet Pakete nicht weiter** | IP-Forwarding ist deaktiviert. | `sudo sysctl -w net.ipv4.ip_forward=1` |
| **Firewall blockiert alles** | Standardrichtlinie ist `DROP`. | Erlaube explizit den gewünschten Verkehr (z. B. `iptables -A FORWARD -i eth0.10 -o eth0.20 -j ACCEPT`). |
| **Ping funktioniert nicht zwischen VLANs** | Firewall-Regel blockiert ICMP. | `sudo iptables -A FORWARD -i eth0.10 -o eth0.20 -p icmp -j ACCEPT` |

## **🎓 Zusammenfassung**

- **IP-Adressen** identifizieren Geräte in Netzwerken (IPv4: 32 Bit, IPv6: 128 Bit).
- **IP-Klassen** (A, B, C, D, E) und **private IP-Bereiche** (RFC 1918) sind wichtig für die Planung.
- **Subnetting** teilt Netzwerke in kleinere Teilnetze auf, um **Adressen effizienter zu nutzen**.
- **CIDR-Notation** (z. B. `/24`) ersetzt die klassische Klassenunterteilung.
- **VLSM** ermöglicht **unterschiedlich große Subnetze** innerhalb eines Netzwerks.
- **Tools wie `ipcalc**` helfen bei der Berechnung von Subnetzen.
