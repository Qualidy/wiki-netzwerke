# 🌐 Tag 3: IP-Adressierung & Subnetting



## **📖 Theorie**



### **1. Einführung in IP-Adressierung**

Eine **IP-Adresse** (Internet Protocol Address) ist eine **eindeutige numerische Adresse**, die jedem Gerät in einem Netzwerk zugewiesen wird, um die **Kommunikation** zu ermöglichen.

#### **Zweck von IP-Adressen**

- **Identifikation:** Eindeutige Kennung eines Geräts im Netzwerk.
- **Lokalisierung:** Bestimmung des **Standorts** eines Geräts (z. B. in einem Subnetz).
- **Routing:** Weiterleitung von Datenpaketen durch das Netzwerk.

---

---

### **2. IPv4 vs. IPv6**


| **Kriterium**       | **IPv4**                        | **IPv6**                                             |
| ------------------- | ------------------------------- | ---------------------------------------------------- |
| **Adresslänge**     | 32 Bit (4 Bytes)                | 128 Bit (16 Bytes)                                   |
| **Anzahl Adressen** | ~4,3 Mrd. (2³²)                 | ~340 Sextillionen (2¹²⁸)                             |
| **Format**          | Dezimal (z. B. `192.168.1.1`)   | Hexadezimal (z. B. `2001:0db8:85a3::8a2e:0370:7334`) |
| **Verwendung**      | Dominierend (90% des Internets) | Zunehmend (z. B. für IoT, Mobilfunk)                 |
| **Vorteile**        | Einfach, weit verbreitet        | Kein NAT nötig, mehr Adressen, bessere Sicherheit    |
| **Nachteile**       | Adressknappheit, NAT nötig      | Komplexere Konfiguration                             |


#### **IPv4-Adressformat**

- **4 Oktette** (jeweils 8 Bit), durch Punkte getrennt.
- **Beispiel:** `192.168.1.1`
    - **Oktett 1:** `192` (Netzwerkanteil)
    - **Oktett 2:** `168` (Netzwerkanteil)
    - **Oktett 3:** `1` (Subnetzanteil)
    - **Oktett 4:** `1` (Hostanteil)

#### **IPv6-Adressformat**

- **8 Blöcke** à 16 Bit, durch Doppelpunkte getrennt.
- **Beispiel:** `2001:0db8:85a3:0000:0000:8a2e:0370:7334`
  - **Verkürzte Schreibweise:**
    - Führende Nullen können weggelassen werden (`2001:db8:85a3:0:0:8a2e:370:7334`).
    - **Doppelte Nullen** können durch `::` ersetzt werden (`2001:db8:85a3::8a2e:370:7334`).

---

---

### **3. IP-Adressklassen (IPv4)**

IPv4-Adressen werden in **5 Klassen** unterteilt, die den **Verwendungszweck** bestimmen.


| **Klasse** | **Bereich**                 | **Erstes Bit** | **Verwendung**                           | **Standard-Subnetzmaske** |
| ---------- | --------------------------- | -------------- | ---------------------------------------- | ------------------------- |
| **A**      | 1.0.0.0 – 126.255.255.255   | 0              | Große Netzwerke (z. B. Regierungen)      | 255.0.0.0 (/8)            |
| **B**      | 128.0.0.0 – 191.255.255.255 | 10             | Mittlere Netzwerke (z. B. Universitäten) | 255.255.0.0 (/16)         |
| **C**      | 192.0.0.0 – 223.255.255.255 | 110            | Kleine Netzwerke (z. B. Unternehmen)     | 255.255.255.0 (/24)       |
| **D**      | 224.0.0.0 – 239.255.255.255 | 1110           | **Multicast** (Gruppenkommunikation)     | –                         |
| **E/R**      | 240.0.0.0 – 255.255.255.255 | 11110           | Reserved (für zukünftige Verwendung)    | –                         |





#### **Spezielle IP-Adressen**


| **Adresse**       | **Bedeutung**                                                         |
| ----------------- | --------------------------------------------------------------------- |
| `0.0.0.0`         | **Standard-Route** (Default Gateway)                                  |
| `127.0.0.1`       | **Loopback** (lokaler Host)                                           |
| `255.255.255.255` | **Broadcast** (alle Geräte im Netzwerk)                               |
| `169.254.x.x`     | **APIPA** (Automatische private IP-Zuweisung, falls DHCP fehlschlägt) |

### **4. Subnetting – Warum und wie?**

**Subnetting** ist die **Aufteilung eines Netzwerks in kleinere Teilnetze (Subnetze)**, um:

- **IP-Adressen effizienter zu nutzen** (Vermeidung von Adressverschwendung).
- **Netzwerkverkehr zu reduzieren** (geringere Broadcast-Domänen).
- **Sicherheit zu erhöhen** (Isolation von Netzwerksegmenten).
- **Routing zu vereinfachen** (bessere Kontrolle über Datenflüsse).

#### **Subnetzmaske**

- Die **Subnetzmaske** bestimmt, welcher Teil der IP-Adresse zum **Netzwerk** und welcher zum **Host** gehört.
- **Beispiel:**
    - IP: `192.168.1.10`
    - Subnetzmaske: `255.255.255.0` (`/24`)
    - **Netzwerkanteil:** `192.168.1`
    - **Hostanteil:** `.10`

#### **CIDR-Notation (Classless Inter-Domain Routing)**

- **Ersetzt die klassische Klassenunterteilung** (A, B, C).
- **Format:** `IP-Adresse/Präfixlänge` (z. B. `192.168.1.0/24`).
- **Präfixlänge:** Anzahl der Bits für den **Netzwerkanteil** (z. B. `/24` = 24 Bits für Netzwerk, 8 Bits für Hosts).


| **Subnetzmaske** | **CIDR-Notation** | **Anzahl Hosts** |
| ---------------- | ----------------- | ---------------- |
| 255.0.0.0        | /8                | 16.777.214       |
| 255.255.0.0      | /16               | 65.534           |
| 255.255.255.0    | /24               | 254              |
| 255.255.255.128  | /25               | 126              |
| 255.255.255.192  | /26               | 62               |
| 255.255.255.224  | /27               | 30               |
| 255.255.255.240  | /28               | 14               |


#### **Berechnung der Anzahl Hosts pro Subnetz**

- **Formel:** `2^(Anzahl Host-Bits) - 2`
    - **-2**, weil **Netzwerkadresse** und **Broadcast-Adresse** nicht für Hosts genutzt werden können.
- **Beispiel für /24:**
    - Host-Bits: `32 - 24 = 8`
    - Anzahl Hosts: `2^8 - 2 = 256 - 2 = 254`

---

### **5. Subnetting Schritt für Schritt**

#### **Beispiel: Netzwerk `192.168.1.0/24` in 4 Subnetze aufteilen**

1. **Anforderung:**
    - 4 Subnetze mit je **mindestens 30 Hosts**.
2. **Host-Bits berechnen:**
    - 30 Hosts → `2^n - 2 ≥ 30` → `n = 5` (2⁵ - 2 = 30).
3. **Netzwerk-Bits:**
    - Ursprünglich: `/24` (24 Bits für Netzwerk).
    - Neue Präfixlänge: `32 - 5 = 27` → **/27**.
4. **Subnetzmaske:**
    - `/27` → `255.255.255.224`.
5. **Subnetze berechnen:**
    - **Subnetz 1:** `192.168.1.0/27` (Hosts: `192.168.1.1` – `192.168.1.30`)
    - **Subnetz 2:** `192.168.1.32/27` (Hosts: `192.168.1.33` – `192.168.1.62`)
    - **Subnetz 3:** `192.168.1.64/27` (Hosts: `192.168.1.65` – `192.168.1.94`)
    - **Subnetz 4:** `192.168.1.96/27` (Hosts: `192.168.1.97` – `192.168.1.126`)

#### **Visualisierung**


| **Subnetz** | **Netzwerkadresse** | **Erste Host-IP** | **Letzte Host-IP** | **Broadcast-Adresse** |
| ----------- | ------------------- | ----------------- | ------------------ | --------------------- |
| Subnetz 1   | 192.168.1.0/27      | 192.168.1.1       | 192.168.1.30       | 192.168.1.31          |
| Subnetz 2   | 192.168.1.32/27     | 192.168.1.33      | 192.168.1.62       | 192.168.1.63          |
| Subnetz 3   | 192.168.1.64/27     | 192.168.1.65      | 192.168.1.94       | 192.168.1.95          |
| Subnetz 4   | 192.168.1.96/27     | 192.168.1.97      | 192.168.1.126      | 192.168.1.127         |

### **6. VLSM (Variable Length Subnet Masking)**

- **Problem:** Bei klassischem Subnetting werden **alle Subnetze gleich groß** erstellt (z. B. 4x /27).
- **Lösung:** **VLSM** ermöglicht **unterschiedlich große Subnetze** innerhalb eines Netzwerks.
- **Beispiel:**
    - Netzwerk: `192.168.1.0/24`
    - **Subnetz 1:** 50 Hosts → `/26` (62 Hosts)
    - **Subnetz 2:** 20 Hosts → `/27` (30 Hosts)
    - **Subnetz 3:** 10 Hosts → `/28` (14 Hosts)

#### **VLSM-Berechnung**

1. **Größtes Subnetz zuerst** (Top-Down-Ansatz).
2. **Subnetz 1 (50 Hosts):**
    - `/26` → `192.168.1.0/26` (Hosts: `192.168.1.1` – `192.168.1.62`).
3. **Subnetz 2 (20 Hosts):**
    - `/27` → `192.168.1.64/27` (Hosts: `192.168.1.65` – `192.168.1.94`).
4. **Subnetz 3 (10 Hosts):**
    - `/28` → `192.168.1.96/28` (Hosts: `192.168.1.97` – `192.168.1.110`).

# 🌐 VLAN-Labor mit VirtualBox: Router als Gateway für Internetzugriff

---

**Ziel:** Ein **funktionierendes VLAN-Labor** mit **3 Ubuntu-VMs** in VirtualBox aufbauen, bei dem **nur die Router-VM zwei Netzwerkkarten** hat (eine für Internet, eine für das interne Netzwerk). Die anderen VMs haben **nur eine Host-Only-Netzwerkkarte** und gehen über den Router ins Internet.

**Dauer:** 2-3 Stunden  
**Voraussetzung:** VirtualBox installiert, 3 Ubuntu Server-VMs (22.04 LTS)

---

---

---

## 📚 **Theorie: Netzwerkaufbau**

### **1. Netzwerk-Topologie**

```
[Internet]
    │
[Router-VM] (enp0s3: NAT für Internet, enp0s8: Host-Only für internes Netzwerk)
    │
    ├── eth0.10 → 192.168.10.1 (VLAN 10, Gateway für VM1)
    │
    └── eth0.20 → 192.168.20.1 (VLAN 20, Gateway für VM2)
         │
[VM1] → 192.168.10.10 (Host-Only, Gateway: 192.168.10.1)
[VM2] → 192.168.20.10 (Host-Only, Gateway: 192.168.20.1)
```

**Ziel:**

- **Router-VM** hat **zwei Netzwerkkarten**:
  - `enp0s3` (NAT) → **Internetzugriff**.
  - `enp0s8` (Host-Only) → **Internes Netzwerk für VLANs**.
- **VM1 und VM2** haben **nur eine Host-Only-Netzwerkkarte** (`enp0s8`) und gehen über den Router ins Internet.
- VM1 und VM2 **können sich nicht direkt** erreichen (unterschiedliche VLANs).
- Der **Router** entscheidet, ob Verkehr zwischen den VLANs erlaubt ist.

---

---

---

## 🛠️ **Praxis: Schritt-für-Schritt-Anleitung für VirtualBox**

---

---

### **📌 Schritt 0: VirtualBox vorbereiten**

**Voraussetzung:**

- **3 Ubuntu Server-VMs** in VirtualBox erstellen (Router-VM, VM1, VM2).

#### **1. Netzwerkadapter der VMs konfigurieren**


| **VM**    | **Adapter 1**  | **Adapter 2**                          |
| --------- | -------------- | -------------------------------------- |
| Router-VM | NAT (`enp0s3`) | Host-Only (`enp0s8`, z. B. `vboxnet0`) |
| VM1       | -              | Host-Only (`enp0s8`, `vboxnet0`)       |
| VM2       | -              | Host-Only (`enp0s8`, `vboxnet0`)       |


**Schritte für jede VM:**

1. VM auswählen → **Einstellungen** → **Netzwerk**.
2. **Router-VM:**
  - **Adapter 1:** **NAT** (für Internetzugriff).
  - **Adapter 2:** **Host-Only Adapter** (z. B. `vboxnet0`).
3. **VM1 und VM2:**
  - **Adapter 1:** **Deaktiviert**.
  - **Adapter 2:** **Host-Only Adapter** (z. B. `vboxnet0`).
4. **OK** klicken.

**Hinweis:**

- **Router-VM** hat **zwei Adapter** (NAT + Host-Only).
- **VM1 und VM2** haben **nur einen Adapter** (Host-Only).

---

---

### **📌 Schritt 1: Router-VM konfigurieren**

**Ziel:** Die Router-VM soll **zwei VLANs (10 und 20)** verwalten, **Internetzugriff ermöglichen** und als **Gateway für VM1 und VM2** dienen.

#### **1. Netzwerkinterfaces prüfen**

Auf der **Router-VM**:

```bash
ip a
```

**Erwartete Ausgabe (Beispiel):**

```
1: lo: <LOOPBACK,UP,LOWER_UP> mtu 65536 qdisc noqueue state UNKNOWN group default qlen 1000
    link/loopback 00:00:00:00:00:00 brd 00:00:00:00:00:00
    inet 127.0.0.1/8 scope host lo
2: enp0s3: <BROADCAST,MULTICAST,UP,LOWER_UP> mtu 1500 qdisc fq_codel state UP group default qlen 1000
    link/ether 08:00:27:xx:xx:xx brd ff:ff:ff:ff:ff:ff
    inet 10.0.2.15/24 brd 10.0.2.255 scope global dynamic enp0s3  # NAT-Interface (Internet)
3: enp0s8: <BROADCAST,MULTICAST,UP,LOWER_UP> mtu 1500 qdisc fq_codel state UP group default qlen 1000
    link/ether 08:00:27:yy:yy:yy brd ff:ff:ff:ff:ff:ff
    inet 192.168.56.10/24 brd 192.168.56.255 scope global dynamic enp0s8  # Host-Only-Interface
```

- `**enp0s3**` = NAT-Interface (für Internetzugriff).
- `**enp0s8**` = Host-Only-Interface (für internes Netzwerk).

#### **2. VLAN-Subinterfaces für das Host-Only-Netzwerk erstellen**

Bearbeite die Netplan-Konfiguration der Router-VM:

```bash
sudo nano /etc/netplan/01-netcfg.yaml
```

**Inhalt:**

```yaml
network:
  version: 2
  renderer: networkd
  ethernets:
    enp0s3:
      dhcp4: true  # NAT-Interface (Internetzugriff)
    enp0s8:
      dhcp4: no    # Host-Only-Interface (für VLANs)
  vlans:
    enp0s8.10:    # VLAN 10 auf enp0s8
      id: 10
      link: enp0s8
      addresses: [192.168.10.1/24]
    enp0s8.20:    # VLAN 20 auf enp0s8
      id: 20
      link: enp0s8
      addresses: [192.168.20.1/24]
```

**Konfiguration anwenden:**

```bash
sudo netplan apply
```

#### **3. IP-Forwarding aktivieren**

```bash
# Temporär aktivieren
sudo sysctl -w net.ipv4.ip_forward=1

# Dauerhaft aktivieren
echo "net.ipv4.ip_forward=1" | sudo tee -a /etc/sysctl.conf
sudo sysctl -p
```

#### **4. NAT für Internetzugriff einrichten**

**Wichtig:** Damit VM1 und VM2 über die Router-VM ins Internet kommen, müssen wir **NAT (Masquerading)** für das NAT-Interface (`enp0s3`) einrichten.

```bash
# NAT (Masquerading) für ausgehende Pakete über enp0s3 aktivieren
sudo iptables -t nat -A POSTROUTING -o enp0s3 -j MASQUERADE

# Forwarding von den VLANs ins Internet erlauben
sudo iptables -A FORWARD -i enp0s8.10 -o enp0s3 -j ACCEPT
sudo iptables -A FORWARD -i enp0s8.20 -o enp0s3 -j ACCEPT

# Antwortverkehr von Internet zu den VLANs erlauben
sudo iptables -A FORWARD -i enp0s3 -o enp0s8.10 -m conntrack --ctstate ESTABLISHED,RELATED -j ACCEPT
sudo iptables -A FORWARD -i enp0s3 -o enp0s8.20 -m conntrack --ctstate ESTABLISHED,RELATED -j ACCEPT

# Regeln speichern
sudo apt install iptables-persistent -y
sudo netfilter-persistent save
```

**Was passiert hier?**


| **Befehl**                                                                                        | **Erklärung**                                                                                                    |
| ------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| `iptables -t nat -A POSTROUTING -o enp0s3 -j MASQUERADE`                                          | **NAT (Masquerading)** für ausgehende Pakete über `enp0s3` (Internet). Alle VMs teilen sich die IP von `enp0s3`. |
| `iptables -A FORWARD -i enp0s8.10 -o enp0s3 -j ACCEPT`                                            | Erlaubt **Forwarding von VLAN 10 ins Internet**.                                                                 |
| `iptables -A FORWARD -i enp0s3 -o enp0s8.10 -m conntrack --ctstate ESTABLISHED,RELATED -j ACCEPT` | Erlaubt **Antwortpakete von Internet zu VLAN 10**.                                                               |

### **📌 Schritt 4: Firewall-Regeln auf der Router-VM**

**Ziel:** Standardmäßig **allen Verkehr zwischen den VLANs blockieren**, aber **Internetzugriff erlauben**.

```bash
# Alle Verbindungen zwischen VLAN 10 und VLAN 20 blockieren
sudo iptables -A FORWARD -i enp0s8.10 -o enp0s8.20 -j DROP
sudo iptables -A FORWARD -i enp0s8.20 -o enp0s8.10 -j DROP

# Regeln speichern
sudo netfilter-persistent save
```

**Was passiert hier?**

- `**iptables -A FORWARD -i enp0s8.10 -o enp0s8.20 -j DROP**` blockiert alle Pakete von VLAN 10 zu VLAN 20.
- `**iptables -A FORWARD -i enp0s8.20 -o enp0s8.10 -j DROP**` blockiert alle Pakete von VLAN 20 zu VLAN 10.

- **Auf VM1:**
  ```bash
  ping 8.8.8.8
  ```
  → **Sollte funktionieren!** (NAT leitet Pakete über `enp0s3` ins Internet weiter.)
- **Auf VM2:**
  ```bash
  ping 8.8.8.8
  ```
  → **Sollte funktionieren!**

#### **2. Ping innerhalb eines VLANs (sollte funktionieren)**

- **Von VM1 zu sich selbst:**
  ```bash
  ping 192.168.10.10
  ```
  → **Funktioniert!** (Lokaler Ping)

#### **3. Ping zwischen VLANs (sollte NICHT funktionieren)**

- **Von VM1 (VLAN 10) zu VM2 (VLAN 20):**
  ```bash
  ping 192.168.20.10
  ```
  → **Funktioniert NICHT!** (Firewall blockiert den Verkehr.)

#### **4. Ping zwischen VLANs erlauben (optional)**

Falls du den Verkehr zwischen den VLANs **erlauben** willst:

```bash
# Erlaube Ping (ICMP) zwischen VLAN 10 und VLAN 20
sudo iptables -A FORWARD -i enp0s8.10 -o enp0s8.20 -p icmp -j ACCEPT
sudo iptables -A FORWARD -i enp0s8.20 -o enp0s8.10 -p icmp -j ACCEPT
sudo netfilter-persistent save
```

→ **Jetzt funktioniert der Ping zwischen VM1 und VM2!**

## 🎓 **Zusammenfassung**

### **Was du gelernt hast:**

✅ **VLANs** trennen Netzwerke logisch, auch wenn sie physisch verbunden sind.  
✅ **Netplan** kann **VLAN-Subinterfaces** einfach konfigurieren.  
✅ **IP-Forwarding** ermöglicht es einem Router, Pakete zwischen Netzwerken weiterzuleiten.  
✅ **NAT (Masquerading)** ermöglicht **Internetzugriff** für VMs hinter einem Router.  
✅ **iptables** kann Verkehr zwischen VLANs **blockieren oder erlauben**.

### **Wichtige Befehle:**


| **Zweck**                         | **Befehl**                                                          |
| --------------------------------- | ------------------------------------------------------------------- |
| VLAN-Subinterface erstellen       | `enp0s8.10: { id: 10, link: enp0s8, addresses: [192.168.10.1/24] }` |
| IP-Forwarding aktivieren          | `sudo sysctl -w net.ipv4.ip_forward=1`                              |
| NAT (Masquerading) aktivieren     | `sudo iptables -t nat -A POSTROUTING -o enp0s3 -j MASQUERADE`       |
| Forwarding für VLANs ins Internet | `sudo iptables -A FORWARD -i enp0s8.10 -o enp0s3 -j ACCEPT`         |
| Firewall-Regel hinzufügen         | `sudo iptables -A FORWARD -i enp0s8.10 -o enp0s8.20 -j DROP`        |
| Firewall-Regeln speichern         | `sudo netfilter-persistent save`                                    |
| Netplan-Konfiguration anwenden    | `sudo netplan apply`                                                |

### **Typische Fehler & Lösungen:**


| **Problem**                            | **Ursache**                   | **Lösung**                                                             |
| -------------------------------------- | ----------------------------- | ---------------------------------------------------------------------- |
| Kein Internetzugriff                   | NAT ist nicht aktiviert       | `sudo iptables -t nat -A POSTROUTING -o enp0s3 -j MASQUERADE`          |
| VLANs funktionieren nicht              | IP-Forwarding ist deaktiviert | `sudo sysctl -w net.ipv4.ip_forward=1`                                 |
| VMs können sich nicht verbinden        | Falsche IP oder Gateway       | Prüfe die Netplan-Konfiguration mit `ip a`                             |
| Firewall blockiert alles               | Standardrichtlinie ist `DROP` | Erlaube explizit den gewünschten Verkehr                               |
| Ping funktioniert nicht zwischen VLANs | Firewall-Regel blockiert ICMP | `sudo iptables -A FORWARD -i enp0s8.10 -o enp0s8.20 -p icmp -j ACCEPT` |
