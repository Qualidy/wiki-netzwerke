# 🔒 Tag 5: Firewall & Netzwerksicherheit (einfach erklärt)



## **📖 Theorie – ganz einfach**

---

### **1. Was ist eine Firewall?**

Stell dir vor, du hast ein **Haus mit einer Tür**.

- **Ohne Firewall:** Jeder kann einfach reinkommen (auch Diebe!).
- **Mit Firewall:** Du hast einen **Pförtner**, der nur **erlaubte Personen** (z. B. Freunde) reinlässt und **ungebetene Gäste** (z. B. Hacker) abweist.

**Eine Firewall ist wie ein Pförtner für dein Netzwerk:**

- Sie **prüft alle Daten**, die rein oder raus wollen.
- Sie **erlaubt oder blockiert** diese Daten nach **Regeln**, die du festlegst.

---

### **2. Wofür braucht man eine Firewall?**


| **Zweck**                       | **Beispiel**                                               |
| ------------------------------- | ---------------------------------------------------------- |
| **Schutz vor Angriffen**        | Blockiert Hacker, die dein Netzwerk angreifen wollen.      |
| **Kontrolle des Datenverkehrs** | Erlaubt nur bestimmte Dienste (z. B. Webseite, E-Mails).   |
| **Verhindern von Datenklau**    | Stoppt Viren oder Schadsoftware, die Daten stehlen wollen. |
| **Netzwerk aufteilen**          | Trennt z. B. das Firmennetzwerk vom GästewLAN.             |


---

### **3. Wie funktioniert eine Firewall?**

Eine Firewall arbeitet mit **Regeln**. Diese Regeln sagen:

- **"Erlaube"** diese Daten (z. B. Webseitenaufrufe).
- **"Blockiere"** diese Daten (z. B. Angriffe).

**Beispiel-Regeln:**

- Erlaube **HTTP (Port 80)** – damit eine Webseite funktioniert.
- Erlaube **SSH (Port 22)** – damit du dich von außen mit deinem Server verbinden kannst.
- Blockiere **alle anderen Ports** – damit niemand unerlaubt rein kann.

---

### **4. Wichtige Begriffe**


| **Begriff**    | **Erklärung**                                                               | **Beispiel**                                            |
| -------------- | --------------------------------------------------------------------------- | ------------------------------------------------------- |
| **Port**       | Eine "Tür" für bestimmte Dienste. Jeder Dienst hat eine eigene Port-Nummer. | Port 80 = HTTP (Webseiten), Port 22 = SSH (Fernzugriff) |
| **IP-Adresse** | Die "Adresse" eines Geräts im Netzwerk.                                     | 192.168.1.1                                             |
| **Paket**      | Ein "Datenpaket", das durchs Netzwerk geschickt wird.                       | Wie ein Brief im Postsystem.                            |
| **Regel**      | Eine Anweisung für die Firewall.                                            | "Erlaube Port 80 für alle."                             |


---

### **5. Firewall-Typen**


| **Typ**               | **Erklärung**                                         | **Beispiel**           |
| --------------------- | ----------------------------------------------------- | ---------------------- |
| **Paketfilter**       | Prüft einzelne Datenpakete.                           | `iptables` (Linux)     |
| **Stateful Firewall** | Merkt sich Verbindungen (z. B. wer schon mal da war). | `ufw` (Ubuntu)         |
| **Proxy-Firewall**    | Agiert als Vermittler zwischen dir und dem Internet.  | Squid (für Webverkehr) |

## **🛠️ Praxis – Firewall mit `ufw` (Ubuntu)**

`ufw` (**Uncomplicated Firewall**) ist eine **einfache Firewall für Ubuntu**, die leicht zu bedienen ist.

---

### **📌 Schritt 1: Firewall aktivieren**

```bash
# Firewall einschalten
sudo ufw enable

# Status prüfen
sudo ufw status
```

**Erwartete Ausgabe:**

```
Status: active
To                         Action      From
--                         ------      ----
Anywhere                   DENY        Anywhere
```

---

### **📌 Schritt 2: Standardregeln setzen**

Standardmäßig soll **alles blockiert** werden, außer was wir explizit erlauben.

```bash
# Alle eingehenden Verbindungen blockieren
sudo ufw default deny incoming

# Alle ausgehenden Verbindungen erlauben (damit wir ins Internet können)
sudo ufw default allow outgoing
```

---

### **📌 Schritt 3: Ports freigeben**

#### **Beispiel 1: Webserver (Port 80 und 443)**

```bash
# HTTP (Port 80) erlauben
sudo ufw allow 80

# HTTPS (Port 443) erlauben
sudo ufw allow 443
```

#### **Beispiel 2: SSH (Port 22) nur für eine bestimmte IP**

```bash
# SSH nur für die IP 192.168.1.100 erlauben
sudo ufw allow from 192.168.1.100 to any port 22
```

#### **Beispiel 3: Ping (ICMP) erlauben**

```bash
# Ping erlauben
sudo ufw allow icmp
```

---

### **📌 Schritt 4: Regeln anzeigen und verwalten**

```bash
# Alle Regeln anzeigen
sudo ufw status numbered

# Beispielausgabe:
# Status: active
#
#      To                         Action      From
#      --                         ------      ----
# [1] 80/tcp                     ALLOW       Anywhere
# [2] 443/tcp                    ALLOW       Anywhere
# [3] 22/tcp                     ALLOW       192.168.1.100
# [4] Anywhere                   DENY        Anywhere
```

---

### **📌 Schritt 5: Regeln löschen**

```bash
# Regel mit der Nummer 3 löschen (z. B. SSH-Regel)
sudo ufw delete 3
```

---

### **📌 Schritt 6: Firewall deaktivieren (falls nötig)**

```bash
sudo ufw disable
```

### **📝 Übung 1: Firewall aktivieren und Status prüfen**

**Aufgabe:**

1. Aktiviere die Firewall auf deiner Ubuntu-VM.
2. Prüfe den Status mit `sudo ufw status`.
3. **Frage:** Was steht in der Ausgabe? Ist die Firewall aktiv?

??? success "Lösung:"

    1. Firewall aktivieren:
      ```bash
      sudo ufw enable
      ```
    2. Status prüfen:
      ```bash
      sudo ufw status
      ```
      **Erwartete Ausgabe:**

          - Die Firewall ist **aktiv** und blockiert **alle eingehenden Verbindungen**.

### **📝 Übung 3: SSH nur für eine IP erlauben**

**Aufgabe:**

1. Erlaube **SSH (Port 22)** nur für die IP **192.168.1.50**.
2. Prüfe, ob die Regel funktioniert, indem du von einer anderen IP (z. B. 192.168.1.60) versuchst, dich per SSH zu verbinden.
3. **Frage:** Warum kann sich die IP 192.168.1.60 nicht verbinden?

??? success "Lösung:"

    1. SSH-Regel hinzufügen:
      ```bash
      sudo ufw allow from 192.168.1.50 to any port 22
      ```
    2. Regeln anzeigen:
      ```bash
      sudo ufw status
      ```
      **Erwartete Ausgabe:**
    3. **Test:**

        - Von **192.168.1.50** aus:
          → **Funktioniert!**
        - Von **192.168.1.60** aus:
          ```bash
          ssh user@deine-vm-ip
          ```
          → **Wird blockiert!**
        - **Grund:** Die Firewall erlaubt SSH **nur für 192.168.1.50**.

### **📝 Übung 4: Ping erlauben oder blockieren**

**Aufgabe:**

1. Erlaube **Ping (ICMP)**.
2. Teste, ob du die VM von einem anderen Gerät aus **pingen** kannst.
3. Blockiere **Ping** wieder.
4. **Frage:** Warum ist Ping manchmal nützlich und manchmal gefährlich?

??? success "Lösung:"

    1. Ping erlauben:
      ```bash
      sudo ufw allow icmp
      ```
    2. Test von einem anderen Gerät:
      ```bash
      ping deine-vm-ip
      ```
      → **Funktioniert!** (Antworten kommen zurück.)
    3. Ping blockieren:
      ```bash
      sudo ufw deny icmp
      ```
    4. **Warum Ping nützlich/gefährlich ist:**


        - **Nützlich:** Prüft, ob ein Gerät **erreichbar** ist (z. B. für Fehlerbehebung).
        - **Gefährlich:** Angreifer können mit Ping **scannen**, welche Geräte im Netzwerk sind.

### **📝 Übung 5: Regel löschen**

**Aufgabe:**

1. Füge eine Regel hinzu, die **Port 3306 (MySQL)** erlaubt.
2. Zeige die Regeln an und merke dir die **Nummer der Regel**.
3. Lösche die Regel wieder.
4. **Frage:** Wie viele Regeln sind jetzt noch aktiv?

??? success "Lösung:"

    1. Port 3306 erlauben:
      ```bash
      sudo ufw allow 3306
      ```
    2. Regeln anzeigen:
      ```bash
      sudo ufw status numbered
      ```
      **Beispielausgabe:**
      - Die MySQL-Regel hat z. B. die **Nummer 4**.
    3. Regel löschen:
      ```bash
      sudo ufw delete 4
      ```
    4. Regeln anzeigen:
      ```bash
      sudo ufw status
      ```
      **Erwartete Ausgabe:**

          - **Aktiv:** 3 Regeln.

### **📝 Übung 6: Firewall zurücksetzen**

**Aufgabe:**

1. Setze die Firewall **komplett zurück** (alle Regeln löschen).
2. Prüfe den Status.
3. **Frage:** Was passiert, wenn du die Firewall zurücksetzt?

??? success "Lösung:"

    1. Firewall zurücksetzen:
      ```bash
      sudo ufw reset
      ```
      → **Bestätige mit "y"**.
    2. Status prüfen:
      ```bash
      sudo ufw status
      ```

    3. **Was passiert?**

        - **Alle Regeln werden gelöscht**.
        - Die Firewall ist **deaktiviert** und erlaubt **allen Verkehr** (unsicher!).
        - **Wichtig:** Immer **neue Regeln hinzufügen**, nachdem du die Firewall zurückgesetzt hast!

### **📝 Übung 7: Einfache Sicherheitsregeln für ein Unternehmen**

**Szenario:**  
Ein kleines Unternehmen hat:

- Einen **Webserver** (Port 80 und 443).
- Einen **SSH-Zugriff** für Administratoren (nur von der IP 203.0.113.5).
- **Keine anderen Dienste** sollen von außen erreichbar sein.

**Aufgabe:**

1. Erstelle die **notwendigen Firewall-Regeln** mit `ufw`.
2. **Frage:** Welche Ports sind freigegeben und für wen?

??? success "Lösung:"

    1. Firewall aktivieren und Standardregeln setzen:
      ```bash
      sudo ufw enable
      sudo ufw default deny incoming
      sudo ufw default allow outgoing
      ```
    2. Webserver-Ports freigeben:
      ```bash
      sudo ufw allow 80
      sudo ufw allow 443
      ```
    3. SSH nur für 203.0.113.5 erlauben:
      ```bash
      sudo ufw allow from 203.0.113.5 to any port 22
      ```
    4. Regeln anzeigen:
      ```bash
      sudo ufw status
      ```

      **Freigegebene Ports:**

      - **Port 80 (HTTP)** und **443 (HTTPS)** für **alle**.
      - **Port 22 (SSH)** nur für **203.0.113.5**.

## **🎓 Zusammenfassung – das Wichtigste**

- **Firewall = Pförtner für dein Netzwerk** → Erlaubt oder blockiert Datenverkehr.
- `**ufw` ist einfach zu bedienen** (perfekt für Anfänger).
- **Wichtige Befehle:**

  | **Befehl**          | **Zweck**                  |
  | ------------------- | -------------------------- |
  | `sudo ufw enable`   | Firewall aktivieren        |
  | `sudo ufw disable`  | Firewall deaktivieren      |
  | `sudo ufw allow 80` | Port 80 freigeben          |
  | `sudo ufw deny 22`  | Port 22 blockieren         |
  | `sudo ufw status`   | Regeln anzeigen            |
  | `sudo ufw delete 1` | Regel mit Nummer 1 löschen |

- **Sicherheitsregeln:**
  - **Standardmäßig alles blockieren** (`deny incoming`).
  - **Nur notwendige Ports freigeben** (z. B. 80, 443, 22).
  - **SSH immer auf bestimmte IPs beschränken** (nicht für alle freigeben!).
