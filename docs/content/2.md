## **📖 Theorie**

---

### **1. Was ist Virtualisierung?**

**Virtualisierung** ermöglicht das **Betreiben mehrerer virtueller Maschinen (VMs)** auf einem **physikalischen Host-System**.  
Jede VM läuft **isoliert** und kann ein eigenes **Betriebssystem (OS)** und **Anwendungen** ausführen.

#### **Vorteile der Virtualisierung**


| **Vorteil**                 | **Beschreibung**                                                                  |
| --------------------------- | --------------------------------------------------------------------------------- |
| **Ressourceneffizienz**     | Mehrere VMs teilen sich die Hardware (CPU, RAM, Festplatte) des Hosts.            |
| **Isolation**               | VMs sind voneinander getrennt – ein Absturz einer VM beeinflusst andere nicht.    |
| **Flexibilität**            | Schnelles Erstellen, Klonen und Löschen von VMs.                                  |
| **Kosteneinsparung**        | Weniger physische Hardware nötig (z. B. für Testumgebungen).                      |
| **Schnelle Bereitstellung** | VMs können in Minuten erstellt und konfiguriert werden.                           |
| **Sicherheit**              | Testen von Software oder Netzwerkkonfigurationen ohne Risiko für das Host-System. |


#### **Nachteile der Virtualisierung**


| **Nachteil**             | **Beschreibung**                                                        |
| ------------------------ | ----------------------------------------------------------------------- |
| **Performance-Overhead** | VMs sind langsamer als physische Maschinen (CPU/RAM wird geteilt).      |
| **Komplexität**          | Verwaltung mehrerer VMs erfordert Wissen (z. B. Netzwerkkonfiguration). |
| **Ressourcenkonflikte**  | Zu viele VMs auf einem Host können zu **Performance-Problemen** führen. |


---

---

### **2. Arten der Virtualisierung**


| **Art**                      | **Beschreibung**                                                                | **Beispiele**                                |
| ---------------------------- | ------------------------------------------------------------------------------- | -------------------------------------------- |
| **Vollvirtualisierung**      | Der **Hypervisor** simuliert eine **komplette Hardware** (CPU, RAM, etc.).      | VMware ESXi, VirtualBox, KVM                 |
| **Paravirtualisierung**      | Der **Hypervisor** stellt eine **abstrakte Hardware-Schnittstelle** bereit.     | Xen, KVM (mit Paravirt-Treibern)             |
| **Containerisierung**        | **Leichtgewichtige Virtualisierung** auf Betriebssystemebene (kein eigenes OS). | Docker, LXC                                  |
| **Hardware-Virtualisierung** | **Dedizierte Hardware** für VMs (z. B. für Hochleistungsanwendungen).           | Bare-Metal-Hypervisor (z. B. VMware vSphere) |


#### **Vergleich: Virtualisierung vs. Containerisierung**


| **Kriterium**           | **Virtualisierung (VMs)**           | **Containerisierung**                               |
| ----------------------- | ----------------------------------- | --------------------------------------------------- |
| **Isolation**           | Hoch (eigenes OS pro VM)            | Mittel (geteilter Kernel)                           |
| **Performance**         | Langsamer (Overhead durch OS)       | Schneller (kein OS-Overhead)                        |
| **Ressourcenverbrauch** | Hoch (eigenes OS pro VM)            | Niedrig (geteilter Kernel)                          |
| **Portabilität**        | Mittel (abhängig vom Hypervisor)    | Hoch (Container laufen auf jedem System mit Docker) |
| **Einsatzzweck**        | Vollständige Systeme (z. B. Server) | Mikroservices, Anwendungen (z. B. Web-Apps)         |


---

---

### **3. Hypervisor – Die Virtualisierungssoftware**

Ein **Hypervisor** ist die Software, die **VMs verwaltet** und die **Hardware-Ressourcen** verteilt.

#### **Typen von Hypervisoren**


| **Typ**                | **Beschreibung**                                               | **Beispiele**                       |
| ---------------------- | -------------------------------------------------------------- | ----------------------------------- |
| **Typ 1 (Bare-Metal)** | Läuft **direkt auf der Hardware** (kein Host-OS nötig).        | VMware ESXi, Microsoft Hyper-V, KVM |
| **Typ 2 (Hosted)**     | Läuft **auf einem Host-Betriebssystem** (z. B. Windows/Linux). | VirtualBox, VMware Workstation      |


#### **Beliebte Hypervisor-Software**


| **Software**                       | **Typ** | **Plattform**         | **Kosten**                    | **Einsatzzweck**            |
| ---------------------------------- | ------- | --------------------- | ----------------------------- | --------------------------- |
| VirtualBox                         | Typ 2   | Windows, Linux, macOS | Kostenlos                     | Entwicklung, Testumgebungen |
| VMware Workstation                 | Typ 2   | Windows, Linux        | Kostenpflichtig               | Professionelle Nutzung      |
| VMware ESXi                        | Typ 1   | Bare-Metal            | Kostenlos (begrenzte Version) | Server-Virtualisierung      |
| KVM (Kernel-based Virtual Machine) | Typ 1   | Linux                 | Kostenlos                     | Server-Virtualisierung      |
| Proxmox VE                         | Typ 1   | Linux (Debian)        | Kostenlos                     | Enterprise-Virtualisierung  |


---

---

### **4. VirtualBox – Überblick**

**VirtualBox** ist ein **kostenloser, plattformübergreifender Hypervisor (Typ 2)** von Oracle.

- **Unterstützte Gast-Betriebssysteme:** Windows, Linux, macOS, BSD, Solaris, etc.
- **Funktionen:**
  - **Snapshots** (Zustände von VMs speichern und wiederherstellen)
  - **Gemeinsame Ordner** (Dateiaustausch zwischen Host und VM)
  - **Netzwerkmodi** (NAT, Bridged, Host-Only, Internal)
  - **USB-Geräteunterstützung**

#### **VirtualBox-Netzwerkmodi im Vergleich**


| **Modus**     | **Beschreibung**                                                            | **Einsatzzweck**                                          |
| ------------- | --------------------------------------------------------------------------- | --------------------------------------------------------- |
| **NAT**       | VM teilt sich die **IP-Adresse des Hosts** (Port-Forwarding möglich).       | Standardmodus für Internetzugriff.                        |
| **Bridged**   | VM erhält eine **eigene IP-Adresse im LAN** (wie ein physikalisches Gerät). | VM soll im Netzwerk wie ein physikalischer PC erscheinen. |
| **Host-Only** | VM kann **nur mit dem Host kommunizieren** (isoliertes Netzwerk).           | Testumgebungen, interne Netzwerke.                        |
| **Internal**  | VMs können **nur miteinander kommunizieren** (kein Zugriff auf Host/LAN).   | Isolierte Testnetzwerke.                                  |

## **🛠️ Praxis: VirtualBox installieren & VM einrichten**

---

### **📌 Schritt 1: VirtualBox installieren**

#### **Windows/macOS/Linux**

1. **Download:**
  - [VirtualBox herunterladen](https://www.virtualbox.org/wiki/Downloads)
  - **Wichtig:** Auch das **VirtualBox Extension Pack** herunterladen (für USB 2.0/3.0, RDP, etc.).
2. **Installation:**
  - Doppelklick auf die heruntergeladene Datei (z. B. `VirtualBox-7.0.12-159484-Win.exe`).
  - **Standardinstallation** wählen (alle Optionen aktiviert lassen).
  - **Extension Pack** nach der Installation von VirtualBox installieren:
    - VirtualBox öffnen → **Datei** → **Einstellungen** → **Erweiterungen** → **Hinzufügen** → Extension Pack auswählen.

---

---

### **📌 Schritt 2: Ubuntu Server VM erstellen**

#### **1. Ubuntu Server ISO herunterladen**

- [Ubuntu Server 22.04 LTS herunterladen](https://ubuntu.com/download/server)
  - **Wichtig:** **Server-Version** (nicht Desktop!) wählen.

#### **2. Neue VM in VirtualBox erstellen**

1. VirtualBox öffnen → **Neu** klicken.
2. **Name:** `Ubuntu-Server-01`
  - **Typ:** `Linux`
  - **Version:** `Ubuntu (64-bit)`  
   → **Weiter**
3. **Arbeitsspeicher (RAM):**
  - **Empfohlen:** **2048 MB (2 GB)** (für Server ausreichend)  
   → **Weiter**
4. **Festplatte:**
  - **Erstelle eine virtuelle Festplatte jetzt** → **Erstellen**
5. **Festplattentyp:**
  - **VDI (VirtualBox Disk Image)** → **Weiter**
6. **Speicher auf physikalischer Festplatte:**
  - **Dynamisch zugewiesen** (spart Platz) → **Weiter**
7. **Dateiname und Größe:**
  - **Größe:** **20 GB** (für Ubuntu Server ausreichend)  
   → **Erstellen**

#### **3. VM konfigurieren**

1. **VM auswählen** → **Einstellungen** klicken.
2. **System:**
  - **Prozessor:** **2 CPU-Kerne** (für bessere Performance)
  - **Boot-Reihenfolge:** **Optisches Laufwerk** zuerst (für Installation)
3. **Anzeige:**
  - **Grafikcontroller:** `VBoxSVGA`
  - **Video-Speicher:** **128 MB**
4. **Netzwerk:**
  - **Adapter 1:**
    - **Aktiviert:** ✅
    - **Anbindung an:** **NAT** (für Internetzugriff)
  - **Adapter 2 (optional für internes Netzwerk):**
    - **Aktiviert:** ✅
    - **Anbindung an:** **Host-Only Adapter** (für Kommunikation zwischen VMs)
5. **Speicher:**
  - **Controller: IDE** → **Leeres CD-Laufwerk auswählen** → **Ubuntu Server ISO hinzufügen**
    - Klick auf das **CD-Symbol** → **Datei auswählen** → ISO-Datei auswählen.

---

---

### **📌 Schritt 3: Ubuntu Server installieren**

1. **VM starten** (grüner Pfeil).
2. **Sprache auswählen:** `Deutsch` oder `English` (empfohlen: **English** für bessere Dokumentation).
3. **Installationsmenü:**
  - **Install Ubuntu Server** auswählen.
4. **Sprache & Region:**
  - **Language:** `English`
  - **Country:** `Germany` (oder passendes Land)
  - **Keyboard Layout:** `German` (oder passend)
5. **Netzwerkkonfiguration:**
  - **Hostname:** `ubuntu-server-01` (oder individuell)
  - **User:** `admin` (oder individuell)
  - **Server Name:** `ubuntu-server-01`
6. **Benutzer erstellen:**
  - **Name:** `admin`
  - **Server Name:** `ubuntu-server-01`
  - **Username:** `admin`
  - **Password:** **Sicheres Passwort** (z. B. `UbuntuServer2026!`)
  - **Confirm Password:** Gleiches Passwort wiederholen.
7. **SSH-Setup:**
  - **Install OpenSSH server?** → **Ja** (für Fernzugriff)
8. **Featured Server Snaps:**
  - **Keine Auswahl** (leer lassen) → **Done**
9. **Installation starten:**
  - **Install** → Bestätigen mit **Enter**.
10. **Warten bis die Installation abgeschlossen ist** (ca. 5–10 Minuten).
11. **Reboot:**
  - **Reboot Now** → VM startet neu.

### **📌 Schritt 4: Basis-Konfiguration der VM**

#### **1. Anmeldung**

- **Benutzername:** `admin`
- **Passwort:** `UbuntuServer2026!` (oder das gewählte Passwort)

#### **2. System aktualisieren**

```bash
sudo apt update && sudo apt upgrade -y
```

#### **3. Benutzer zu sudoers hinzufügen (falls nicht automatisch)**

```bash
sudo usermod -aG sudo admin
```

#### **4. Hostname prüfen/ändern**

```bash
# Hostname anzeigen
hostname

# Hostname ändern (z. B. in "server1")
sudo hostnamectl set-hostname server1
```

#### **5. Netzwerkkonfiguration prüfen**

```bash
# IP-Adresse anzeigen (NAT-Modus)
ip a

# oder
ifconfig
```

- **Hinweis:** Im **NAT-Modus** erhält die VM eine **private IP** (z. B. `10.0.2.15`).  
Für **Bridged-Modus** oder **Host-Only** muss die Netzwerkkonfiguration angepasst werden.

#### **6. Statische IP-Adresse einrichten (optional für Host-Only-Netzwerk)**

1. **Netzwerk-Interface prüfen:**
  ```bash
   ip a
  ```
  - Beispielausgabe:
    ```
    2: enp0s3: <BROADCAST,MULTICAST,UP,LOWER_UP> mtu 1500 qdisc fq_codel state UP group default qlen 1000
        link/ether 08:00:27:xx:xx:xx brd ff:ff:ff:ff:ff:ff
        inet 10.0.2.15/24 brd 10.0.2.255 scope global dynamic enp0s3
    ```
  - **Interface:** `enp0s3` (kann abweichen, z. B. `ens33`)
2. **Netzwerkkonfiguration bearbeiten:**
  ```bash
   sudo nano /etc/netplan/00-installer-config.yaml
  ```
  - **Inhalt anpassen** (Beispiel für Host-Only-Netzwerk mit IP `192.168.56.10`):
    ```yaml
    network:
      version: 2
      renderer: networkd
      ethernets:
        enp0s3:
          dhcp4: no
          addresses: [192.168.56.10/24]
          gateway4: 192.168.56.1
          nameservers:
            addresses: [8.8.8.8, 8.8.4.4]
    ```
  - **Speichern:** `Strg + O` → `Enter` → `Strg + X`
3. **Netzwerk neu starten:**
  ```bash
   sudo netplan apply
  ```
4. **IP-Adresse prüfen:**
  ```bash
   ip a
  ```
  - Sollte jetzt `192.168.56.10` anzeigen.

### **📌 Schritt 5: Zweite VM erstellen & Kommunikation testen**

1. **Zweite VM (`Ubuntu-Server-02`) erstellen** (gleiche Schritte wie oben).
2. **Netzwerkmodus anpassen:**
  - **Adapter 1:** NAT (für Internetzugriff)
  - **Adapter 2:** **Host-Only Adapter** (für interne Kommunikation)
3. **Statische IP für die zweite VM einrichten:**
  - **IP:** `192.168.56.11`
  - **Gateway:** `192.168.56.1`
4. **Kommunikation testen:**
  - **Von VM1 (192.168.56.10) zu VM2 (192.168.56.11) pingen:**
  - **Erwartetes Ergebnis:**
    ```
    PING 192.168.56.11 (192.168.56.11) 56(84) bytes of data.
    64 bytes from 192.168.56.11: icmp_seq=1 ttl=64 time=0.512 ms
    ```
  - **Abbruch:** `Strg + C`

### **📝 Aufgabe 2: Netzwerkmodi in VirtualBox testen**

**Beschreibung:**

1. Erstelle eine **zweite VM** (`Ubuntu-Server-02`).
2. Konfiguriere die **Netzwerkadapter** wie folgt:
  - **VM1 (`Ubuntu-Server-01`):**
    - Adapter 1: **NAT** (für Internet)
    - Adapter 2: **Host-Only Adapter** (für internes Netzwerk)
  - **VM2 (`Ubuntu-Server-02`):**
    - Adapter 1: **NAT** (für Internet)
    - Adapter 2: **Host-Only Adapter** (für internes Netzwerk)
3. Weise beiden VMs **statische IPs** im Host-Only-Netzwerk zu:
  - VM1: `192.168.56.10`
  - VM2: `192.168.56.11`
4. Teste die **Kommunikation** zwischen den VMs:
  - Ping von VM1 zu VM2 (`ping 192.168.56.11`).
  - Ping von VM2 zu VM1 (`ping 192.168.56.10`).

**Fragen:**

1. Warum funktioniert der Ping **nicht**, wenn nur **Adapter 1 (NAT)** aktiviert ist?
2. Welcher **Netzwerkmodus** wäre geeignet, wenn die VMs **direkt im LAN** des Hosts erscheinen sollen?
3. Wie kannst du prüfen, ob die VMs **Internetzugriff** haben?

**Lösung:**

Lösung anzeigen

1. **Ping funktioniert nicht mit nur NAT:**
  - Im **NAT-Modus** erhalten beide VMs **private IPs** (z. B. `10.0.2.15` und `10.0.2.16`), die **nicht direkt miteinander kommunizieren** können.
  - **Host-Only Adapter** ermöglicht die Kommunikation über ein **internes Netzwerk** (`192.168.56.0/24`).
2. **Netzwerkmodus für LAN-Integration:**
  - **Bridged Adapter** – Die VMs erhalten eine **IP aus dem LAN des Hosts** und erscheinen wie physische Geräte.
3. **Internetzugriff prüfen:**
  - **Befehl:**
  - **Erwartetes Ergebnis:**
    ```
    PING 8.8.8.8 (8.8.8.8) 56(84) bytes of data.
    64 bytes from 8.8.8.8: icmp_seq=1 ttl=117 time=12.3 ms
    ```
  - Falls kein Ping möglich ist:
    - Prüfe, ob **Adapter 1 (NAT)** aktiviert ist.
    - Prüfe die **Firewall** (`sudo ufw status` – sollte `inactive` sein).

### **📝 Aufgabe 3: Benutzerverwaltung & Paketmanagement**

**Beschreibung:**

1. Erstelle auf deiner VM einen **neuen Benutzer** mit dem Namen `testuser` und dem Passwort `Test1234!`.
2. Füge den Benutzer zur **sudo-Gruppe** hinzu.
3. Installiere das Paket `**htop**` (Systemmonitoring-Tool).
4. Starte `htop` und beobachte die **CPU- und RAM-Auslastung**.

**Fragen:**

1. Welcher Befehl wird verwendet, um einen **neuen Benutzer** zu erstellen?
2. Wie kannst du prüfen, ob der Benutzer `**testuser**` zur `sudo`-Gruppe gehört?
3. Welcher Befehl zeigt die **installierten Pakete** an?

**Lösung:**

Lösung anzeigen

1. **Benutzer erstellen:**
  ```bash
   sudo adduser testuser
  ```
  - Passwort: `Test1234!` (zweimal eingeben)
  - Weitere Fragen mit `Enter` bestätigen.
2. **Benutzer zur sudo-Gruppe hinzufügen:**
  ```bash
   sudo usermod -aG sudo testuser
  ```
  - **Prüfen:**
    ```bash
    groups testuser
    ```
  - **Erwartete Ausgabe:**
    ```
    testuser : testuser sudo
    ```
3. **Paket `htop` installieren:**
  ```bash
   sudo apt install htop -y
  ```
  - **Starten:**
    ```bash
    htop
    ```
  - **Beenden:** `F10` oder `Strg + C`

### **📝 Aufgabe 4: Netzwerkdiagnose**

**Beschreibung:**

1. Auf **VM1 (`192.168.56.10`)**:
  - Starte einen **einfachen HTTP-Server** mit Python:
    - python3 -m http.server 8000
    - http://localhost:8000

2. Auf **VM2 (`192.168.56.11`)**:
  - Versuche, auf den Server von VM1 zuzugreifen:
  - Alternativ: **Browser** öffnen (falls GUI installiert) und `http://192.168.56.10:8000` aufrufen.

**Fragen:**

1. Warum funktioniert der Zugriff **nicht**, wenn der **HTTP-Server auf Port 80** läuft?
2. Wie kannst du prüfen, ob der **Port 8000** auf VM1 offen ist?
3. Welcher Befehl zeigt die **offenen Ports** auf einer VM an?

**Lösung:**

Lösung anzeigen

1. **Zugriff auf Port 80 funktioniert nicht:**
  - **Standardmäßig** blockiert die **Firewall** (`ufw`) oder **VirtualBox** den Zugriff auf Port 80.
  - **Lösung:**
    - Firewall deaktivieren:
      ```bash
      sudo ufw disable
      ```
    - Oder Port 80 freigeben:
      ```bash
      sudo ufw allow 80
      ```
2. **Port 8000 prüfen:**
  - **Von VM2 aus:**
  - **Erwartetes Ergebnis:**
    ```
    Trying 192.168.56.10...
    Connected to 192.168.56.10.
    Escape character is '^]'.
    ```
    → Verbindung erfolgreich.
3. **Offene Ports anzeigen:**
  ```bash
   sudo netstat -tuln
  ```
   oder
  - **Erwartete Ausgabe (für Python-Server):**
    ```
    tcp   0   0 0.0.0.0:8000   0.0.0.0:*   LISTEN
    ```

## **🎓 Zusammenfassung**

- **Virtualisierung** ermöglicht das **Betreiben mehrerer VMs auf einem Host**.
- **VirtualBox** ist ein **kostenloser Hypervisor (Typ 2)** für Testumgebungen.
- **Ubuntu Server** kann in VirtualBox **einfach installiert und konfiguriert** werden.
- **Netzwerkmodi** in VirtualBox:
  - **NAT:** Internetzugriff, aber keine direkte Kommunikation zwischen VMs.
  - **Bridged:** VM erscheint wie ein physikalisches Gerät im LAN.
  - **Host-Only:** Isoliertes Netzwerk für VMs und Host.
  - **Internal:** Nur Kommunikation zwischen VMs möglich.
- **Basis-Konfiguration** einer VM:
  - Benutzerverwaltung (`adduser`, `usermod`)
  - Paketmanagement (`apt install`, `apt update`)
  - Netzwerkkonfiguration (`netplan`, `ip a`)
