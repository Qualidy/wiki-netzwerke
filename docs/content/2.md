# 🖥️ Tag 2: Virtualisierung & VM-Setup mit Hyper-V

---


## **📖 Theorie**

---


### **1. Was ist Virtualisierung?**

**Virtualisierung** ermöglicht das **Betreiben mehrerer virtueller Maschinen (VMs)** auf einem **physikalischen Host-System**.  
Jede VM läuft **isoliert** und kann ein eigenes **Betriebssystem (OS)** und **Anwendungen** ausführen.

#### **Vorteile der Virtualisierung**


| **Vorteil**                 | **Beschreibung**                                                                  |
| --------------------------- | --------------------------------------------------------------------------------- |
| **Ressourceneffizienz**     | Mehrere VMs teilen sich die Hardware (CPU, RAM, Festplatte) des Hosts.            |
| **Isolation**               | VMs sind voneinander getrennt – ein Absturz einer VM beeinflusst andere nicht.    |
| **Flexibilität**            | Schnelles Erstellen, Klonen und Löschen von VMs.                                  |
| **Kosteneinsparung**        | Weniger physische Hardware nötig (z. B. für Testumgebungen).                      |
| **Schnelle Bereitstellung** | VMs können in Minuten erstellt und konfiguriert werden.                           |
| **Sicherheit**              | Testen von Software oder Netzwerkkonfigurationen ohne Risiko für das Host-System. |


#### **Nachteile der Virtualisierung**


| **Nachteil**             | **Beschreibung**                                                        |
| ------------------------ | ----------------------------------------------------------------------- |
| **Performance-Overhead** | VMs sind langsamer als physische Maschinen (CPU/RAM wird geteilt).      |
| **Komplexität**          | Verwaltung mehrerer VMs erfordert Wissen (z. B. Netzwerkkonfiguration). |
| **Ressourcenkonflikte**  | Zu viele VMs auf einem Host können zu Performance-Problemen führen.     |


---

---

### **2. Arten der Virtualisierung**


| **Art**                      | **Beschreibung**                                                            | **Beispiele**                                |
| ---------------------------- | --------------------------------------------------------------------------- | -------------------------------------------- |
| **Vollvirtualisierung**      | Der Hypervisor simuliert eine komplette Hardware (CPU, RAM, etc.).          | VMware ESXi, **Hyper-V**, KVM                |
| **Paravirtualisierung**      | Der Hypervisor stellt eine abstrakte Hardware-Schnittstelle bereit.         | Xen, KVM (mit Paravirt-Treibern)             |
| **Containerisierung**        | Leichtgewichtige Virtualisierung auf Betriebssystemebene (kein eigenes OS). | Docker, LXC                                  |
| **Hardware-Virtualisierung** | Dedizierte Hardware für VMs (z. B. für Hochleistungsanwendungen).           | Bare-Metal-Hypervisor (z. B. VMware vSphere) |


#### **Vergleich: Virtualisierung vs. Containerisierung**


| **Kriterium**           | **Virtualisierung (VMs)**           | **Containerisierung**                               |
| ----------------------- | ----------------------------------- | --------------------------------------------------- |
| **Isolation**           | Hoch (eigenes OS pro VM)            | Mittel (geteilter Kernel)                           |
| **Performance**         | Langsamer (Overhead durch OS)       | Schneller (kein OS-Overhead)                        |
| **Ressourcenverbrauch** | Hoch (eigenes OS pro VM)            | Niedrig (geteilter Kernel)                          |
| **Portabilität**        | Mittel (abhängig vom Hypervisor)    | Hoch (Container laufen auf jedem System mit Docker) |
| **Einsatzzweck**        | Vollständige Systeme (z. B. Server) | Mikroservices, Anwendungen (z. B. Web-Apps)         |


---

---

### **3. Hypervisor – Die Virtualisierungssoftware**

Ein **Hypervisor** ist die Software, die **VMs verwaltet** und die **Hardware-Ressourcen** verteilt.

#### **Typen von Hypervisoren**


| **Typ**                | **Beschreibung**                                                | **Beispiele**                           |
| ---------------------- | --------------------------------------------------------------- | --------------------------------------- |
| **Typ 1 (Bare-Metal)** | Läuft **direkt auf der Hardware** (ohne Host-Betriebssystem).   | VMware ESXi, **Microsoft Hyper-V**, KVM |
| **Typ 2 (Hosted)**     | Läuft **auf einem Host-Betriebssystem** (z. B. Windows, Linux). | VirtualBox, VMware Workstation          |


#### **Beliebte Hypervisor-Software**


| **Software** | **Typ** | **Plattform**                              | **Kosten**                       | **Einsatzzweck**                       |
| ------------ | ------- | ------------------------------------------ | -------------------------------- | -------------------------------------- |
| **Hyper-V**  | Typ 1   | Windows (ab Windows 8 Pro, Windows Server) | Kostenlos (in Windows enthalten) | Server-Virtualisierung, Testumgebungen |
| VirtualBox   | Typ 2   | Windows, Linux, macOS                      | Kostenlos                        | Entwicklung, Testumgebungen            |
| VMware ESXi  | Typ 1   | Bare-Metal                                 | Kostenlos (begrenzte Version)    | Server-Virtualisierung                 |
| KVM          | Typ 1   | Linux                                      | Kostenlos                        | Server-Virtualisierung                 |


---

---

### **4. Hyper-V – Überblick**

**Hyper-V** ist ein **Hypervisor von Microsoft**, der in **Windows 10/11 Pro/Enterprise und Windows Server** enthalten ist.

- **Unterstützte Gast-Betriebssysteme:** Windows, Linux (z. B. Ubuntu, Debian, CentOS), FreeBSD.
- **Funktionen:**
  - **Snapshots** (Zustände von VMs speichern und wiederherstellen).
  - **Dynamische Speicherzuweisung** (RAM wird je nach Bedarf zugewiesen).
  - **Netzwerkmodi** (Extern, Intern, Privat, NAT).
  - **Integration Services** (bessere Performance für Linux-VMs).

#### **Hyper-V-Netzwerkmodi im Vergleich**


| **Modus**  | **Beschreibung**                                                                                 | **Einsatzzweck**                                  |
| ---------- | ------------------------------------------------------------------------------------------------ | ------------------------------------------------- |
| **Extern** | VM erhält eine **IP aus dem physikalischen Netzwerk** (wie ein physikalisches Gerät).            | VM soll im LAN wie ein normales Gerät erscheinen. |
| **Intern** | VMs können **nur miteinander kommunizieren** (kein Zugriff auf das Host-Netzwerk oder Internet). | Isolierte Testnetzwerke.                          |
| **Privat** | VMs können **nur untereinander kommunizieren** (kein Zugriff auf Host oder Internet).            | Isolierte Testumgebungen.                         |
| **NAT**    | VMs teilen sich eine **IP-Adresse des Hosts** (für Internetzugriff).                             | Standardmodus für Internetzugriff.                |

## **🛠️ Praxis: Hyper-V einrichten & VM erstellen**

---

---

### **📌 Schritt 0: Hyper-V aktivieren (falls noch nicht geschehen)**

#### **Auf Windows 10/11 Pro oder Windows Server:**

1. **Hyper-V aktivieren (über PowerShell als Administrator):**
  ```powershell
   Enable-WindowsOptionalFeature -Online -FeatureName Microsoft-Hyper-V -All
  ```
2. **Neustart durchführen:**
  ```powershell
   Restart-Computer
  ```
3. **Prüfen, ob Hyper-V aktiv ist:**
  ```powershell
   Get-WindowsOptionalFeature -Online -FeatureName Microsoft-Hyper-V
  ```
  - **Erwartet:** `State : Enabled`

---

---

### **📌 Schritt 1: Ubuntu Server ISO herunterladen**

- [Ubuntu Server 22.04 LTS herunterladen](https://ubuntu.com/download/server)
  - **Wichtig:** **Server-Version** (nicht Desktop!) wählen.

---

---

### **📌 Schritt 2: Neue VM in Hyper-V erstellen**

#### **Option 1: Über Hyper-V-Manager (GUI)**

1. **Hyper-V-Manager öffnen** (Suche nach "Hyper-V-Manager" im Startmenü).
2. **Neue VM erstellen:**
    - Rechtsklick auf deinen **Host** → **Neu** → **Virtueller Computer**.
3. **Name und Speicherort:**
    - **Name:** `Ubuntu-Server-01`
    - **Speicherort:** Standard oder benutzerdefiniert → **Weiter**.
4. **Generation auswählen:**
    - **Generation 2** (empfohlen für Ubuntu) → **Weiter**.
5. **Arbeitsspeicher zuweisen:**
    - **2048 MB (2 GB)** → **Weiter**.
6. **Netzwerk konfigurieren:**
    - **Netzwerkadapter:** **Extern** (für Internetzugriff) oder **NAT** (falls kein externes Netzwerk verfügbar) → **Weiter**.
7. **Festplatte erstellen:**
    - **Größe:** **20 GB** (dynamisch erweitern) → **Weiter**.
8. **Installationsoptionen:**
    - **Betriebssystem von einer Start-CD/DVD installieren** → **Weiter**.
    - **Ubuntu Server ISO auswählen** → **Fertig stellen**.

#### **Option 2: Über PowerShell (für Fortgeschrittene)**

```powershell
# Neue VM erstellen
New-VM -Name "Ubuntu-Server-01" -MemoryStartupBytes 2GB -NewVHDPath "C:\VMs\Ubuntu-Server-01.vhdx" -NewVHDSizeBytes 20GB -Generation 2

# Netzwerkadapter hinzufügen (Extern)
Add-VMNetworkAdapter -VMName "Ubuntu-Server-01" -SwitchName "Externer Switch"

# DVD-Laufwerk mit ISO verbinden
Add-VMDvdDrive -VMName "Ubuntu-Server-01" -Path "C:\Pfad\zu\ubuntu-22.04-live-server-amd64.iso"

# VM starten
Start-VM -Name "Ubuntu-Server-01"
```

---

---

### **📌 Schritt 3: Ubuntu Server installieren**

1. **VM starten** (im Hyper-V-Manager: Rechtsklick auf die VM → **Verbinden**).
2. **Sprache auswählen:** `English` (empfohlen für bessere Dokumentation).
3. **Installationsmenü:**
    - **Install Ubuntu Server** auswählen.
4. **Sprache & Region:**
    - **Language:** `English`
    - **Country:** `Germany` (oder passendes Land)
    - **Keyboard Layout:** `German`
5. **Netzwerkkonfiguration:**
    - **Hostname:** `ubuntu-server-01`
    - **User:** `admin`
    - **Server Name:** `ubuntu-server-01`
6. **Benutzer erstellen:**
    - **Name:** `admin`
    - **Username:** `admin`
    - **Password:** **Sicheres Passwort** (z. B. `UbuntuServer2026!`)
    - **Confirm Password:** Gleiches Passwort wiederholen.
7. **SSH-Setup:**
    - **Install OpenSSH server?** → **Ja** (für Fernzugriff).
8. **Featured Server Snaps:**
    - **Keine Auswahl** (leer lassen) → **Done**.
9. **Installation starten:**
    - **Install** → Bestätigen mit **Enter**.
10. **Warten, bis die Installation abgeschlossen ist** (ca. 5–10 Minuten).
11. **Reboot:**
    - **Reboot Now** → VM startet neu.

---

---

### **📌 Schritt 4: Basis-Konfiguration der VM**

#### **1. Anmeldung**

  - **Benutzername:** `admin`
  - **Passwort:** `UbuntuServer2026!` (oder das gewählte Passwort).

#### **2. System aktualisieren**

```bash
sudo apt update && sudo apt upgrade -y
```

#### **3. Benutzer zu sudoers hinzufügen (falls nicht automatisch)**

```bash
sudo usermod -aG sudo admin
```

#### **4. Hostname prüfen/ändern**

```bash
# Hostname anzeigen
hostname

# Hostname ändern (z. B. in "server1")
sudo hostnamectl set-hostname server1
```

#### **5. Netzwerkkonfiguration prüfen**

```bash
# IP-Adresse anzeigen
ip a

# oder
ifconfig
```

  - **Hinweis:** Im **NAT-Modus** erhält die VM eine **private IP** (z. B. `192.168.1.100`).  
  Im **Externen Modus** erhält die VM eine **IP aus deinem LAN**.

#### **6. Statische IP-Adresse einrichten (optional für Externes Netzwerk)**

1. **Netzwerk-Interface prüfen:**
  ```bash
   ip a
  ```
  - Beispielausgabe:
    ```
    2: eth0: <BROADCAST,MULTICAST,UP,LOWER_UP> mtu 1500 qdisc mq state UP group default qlen 1000
        link/ether 00:15:5d:01:02:03 brd ff:ff:ff:ff:ff:ff
        inet 192.168.1.100/24 brd 192.168.1.255 scope global dynamic eth0
    ```
  - **Interface:** `eth0` (kann abweichen, z. B. `ens18`).
2. **Netzwerkkonfiguration bearbeiten:**
  ```bash
   sudo nano /etc/netplan/00-installer-config.yaml
  ```
  - **Inhalt anpassen** (Beispiel für statische IP `192.168.1.10`):
    ```yaml
    network:
      version: 2
      renderer: networkd
      ethernets:
        eth0:
          dhcp4: no
          addresses: [192.168.1.10/24]
          gateway4: 192.168.1.1
          nameservers:
            addresses: [8.8.8.8, 8.8.4.4]
    ```
  - **Speichern:** `Strg + O` → `Enter` → `Strg + X`.
3. **Netzwerk neu starten:**
  ```bash
   sudo netplan apply
  ```
4. **IP-Adresse prüfen:**
  ```bash
   ip a
  ```
  - Sollte jetzt `192.168.1.10` anzeigen.

---

### **📌 Schritt 5: Zweite VM erstellen & Kommunikation testen**

1. **Zweite VM (`Ubuntu-Server-02`) erstellen** (gleiche Schritte wie oben).
    - **Netzwerkmodus:** **Extern** (für Kommunikation zwischen den VMs).
2. **Statische IP für die zweite VM einrichten:**
    - **IP:** `192.168.1.11`
    - **Gateway:** `192.168.1.1` (dein Router).
3. **Kommunikation testen:**
    - **Von VM1 (192.168.1.10) zu VM2 (192.168.1.11) pingen:**
    - **Erwartetes Ergebnis:**
      ```
      PING 192.168.1.11 (192.168.1.11) 56(84) bytes of data.
      64 bytes from 192.168.1.11: icmp_seq=1 ttl=64 time=0.512 ms
      ```
    - **Abbruch:** `Strg + C`.

### **📝 Aufgabe 2: Netzwerkmodi in Hyper-V testen**

**Beschreibung:**

1. Erstelle eine **zweite VM** (`Ubuntu-Server-02`).
2. Konfiguriere die **Netzwerkadapter** wie folgt:
  - **VM1 (`Ubuntu-Server-01`):**
    - Netzwerkadapter: **Extern** (für Internet und Kommunikation mit VM2).
  - **VM2 (`Ubuntu-Server-02`):**
    - Netzwerkadapter: **Extern** (für Internet und Kommunikation mit VM1).
3. Weise beiden VMs **statische IPs** zu:
  - VM1: `192.168.1.10`
  - VM2: `192.168.1.11`
4. Teste die **Kommunikation** zwischen den VMs:
  - Ping von VM1 zu VM2 (`ping 192.168.1.11`).
  - Ping von VM2 zu VM1 (`ping 192.168.1.10`).

**Fragen:**

1. Warum funktioniert der Ping **nicht**, wenn der **Netzwerkmodus auf "Privat"** eingestellt ist?
2. Welcher **Netzwerkmodus** wäre geeignet, wenn die VMs **keinen Internetzugriff** haben sollen, aber miteinander kommunizieren können?
3. Wie kannst du prüfen, ob die VMs **Internetzugriff** haben?

??? success "Lösung:"


    1. **Ping funktioniert nicht mit "Privat":**
        - Im **Privat-Modus** können VMs **nur untereinander kommunizieren**, aber **nicht mit dem Host oder dem Internet**.
        - Für Ping zwischen VMs **muss der Modus auf "Extern" oder "Intern"** eingestellt sein.

    2. **Netzwerkmodus für interne Kommunikation ohne Internet:**
        - **Interner Modus** – VMs können **nur untereinander kommunizieren**, aber nicht mit dem Host oder Internet.

    3. **Internetzugriff prüfen:**
        - **Befehl:**
          ```bash
          ping 8.8.8.8
          ```
        - **Erwartetes Ergebnis:**
          ```
          PING 8.8.8.8 (8.8.8.8) 56(84) bytes of data.
          64 bytes from 8.8.8.8: icmp_seq=1 ttl=117 time=12.3 ms
          ```
        - Falls kein Ping möglich ist:
          - Prüfe, ob der **Netzwerkmodus auf "Extern"** eingestellt ist.
          - Prüfe die **Firewall** (`sudo ufw status` – sollte `inactive` sein).

### **📝 Aufgabe 3: Benutzerverwaltung & Paketmanagement**

**Beschreibung:**

1. Erstelle auf deiner VM einen **neuen Benutzer** mit dem Namen `testuser` und dem Passwort `Test1234!`.
2. Füge den Benutzer zur **sudo-Gruppe** hinzu.
3. Installiere das Paket `**htop**` (Systemmonitoring-Tool).
4. Starte `htop` und beobachte die **CPU- und RAM-Auslastung**.

**Fragen:**

1. Welcher Befehl wird verwendet, um einen **neuen Benutzer** zu erstellen?
2. Wie kannst du prüfen, ob der Benutzer `**testuser**` zur `sudo`-Gruppe gehört?
3. Welcher Befehl zeigt die **installierten Pakete** an?

??? success "Lösung:"


    1. **Benutzer erstellen:**

      ```bash
      sudo adduser testuser
      ```
      - Passwort: `Test1234!` (zweimal eingeben).
      - Weitere Fragen mit `Enter` bestätigen.

    2. **Benutzer zur sudo-Gruppe hinzufügen:**

      ```bash
      sudo usermod -aG sudo testuser
      ```
      - **Prüfen:**
        ```bash
        groups testuser
        ```
      - **Erwartete Ausgabe:**
        ```
        testuser : testuser sudo
        ```

    3. **Paket `htop` installieren:**

      ```bash
      sudo apt install htop -y
      ```
      - **Starten:**
        ```bash
        htop
        ```
      - **Beenden:** `F10` oder `Strg + C`.

### **📝 Aufgabe 4: Netzwerkdiagnose**

**Beschreibung:**

1. Auf **VM1 (`192.168.1.10`)**:
  - Starte einen **einfachen HTTP-Server** mit Python:
2. Auf **VM2 (`192.168.1.11`)**:
  - Versuche, auf den Server von VM1 zuzugreifen:
  - Alternativ: **Browser** öffnen (falls GUI installiert) und `http://192.168.1.10:8000` aufrufen.

**Fragen:**

1. Warum funktioniert der Zugriff **nicht**, wenn der **HTTP-Server auf Port 80** läuft?
2. Wie kannst du prüfen, ob der **Port 8000** auf VM1 offen ist?
3. Welcher Befehl zeigt die **offenen Ports** auf einer VM an?

??? success "Lösung:"


    1. **Zugriff auf Port 80 funktioniert nicht:**

      - **Standardmäßig** blockiert die **Firewall** (`ufw`) oder **Hyper-V** den Zugriff auf Port 80.
      - **Lösung:**
        - Firewall deaktivieren:
          ```bash
          sudo ufw disable
          ```
        - Oder Port 80 freigeben:
          ```bash
          sudo ufw allow 80
          ```

    2. **Port 8000 prüfen:**

      - **Von VM2 aus:**
        ```bash
        telnet 192.168.1.10 8000
        ```
      - **Erwartetes Ergebnis:**
        ```
        Trying 192.168.1.10...
        Connected to 192.168.1.10.
        Escape character is '^]'.
        ```
        → Verbindung erfolgreich.

    3. **Offene Ports anzeigen:**
    
      ```bash
      sudo netstat -tuln
      ```
      oder
      ```bash
      ss -tuln
      ```
      - **Erwartete Ausgabe (für Python-Server):**
        ```
        tcp   0   0 0.0.0.0:8000   0.0.0.0:*   LISTEN
        ```

## **🎓 Zusammenfassung**

- **Virtualisierung** ermöglicht das **Betreiben mehrerer VMs auf einem Host**.
- **Hyper-V** ist ein **kostenloser Hypervisor (Typ 1)** von Microsoft für Windows.
- **Ubuntu Server** kann in Hyper-V **einfach installiert und konfiguriert** werden.
- **Netzwerkmodi in Hyper-V:**
  - **Extern:** VM erhält eine IP aus dem LAN (für Internetzugriff).
  - **Intern:** VMs können nur untereinander kommunizieren (isoliertes Netzwerk).
  - **Privat:** VMs können nur untereinander kommunizieren (kein Zugriff auf Host oder Internet).
  - **NAT:** VMs teilen sich eine IP des Hosts (für Internetzugriff).
- **Basis-Konfiguration** einer VM:
  - Benutzerverwaltung (`adduser`, `usermod`).
  - Paketmanagement (`apt install`, `apt update`).
  - Netzwerkkonfiguration (`netplan`, `ip a`).

## **📌 Tipps für Hyper-V**

- **Hyper-V-Manager** ist die **GUI für die Verwaltung** von VMs.
- **PowerShell** bietet **mehr Kontrolle** für Fortgeschrittene.
- **Integration Services** für Linux-VMs installieren (für bessere Performance):
  ```bash
  sudo apt install linux-cloud-tools -y
  ```
- **Snapshots** erstellen, um den Zustand einer VM zu speichern (für Tests).
