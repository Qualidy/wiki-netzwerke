# 🌐 Tag 6: Webserver (Apache/Nginx) - Einfach erklärt



## **📚 Theorie – ganz einfach erklärt**

---

---

### **1. Was ist ein Webserver?**

Stell dir vor, du hast ein **Restaurant**:

- **Webserver = Kellner**, der **Bestellungen (Requests)** entgegennimmt und **Gerichte (Webseiten)** serviert.
- **Client (z. B. dein Browser) = Gast**, der eine Bestellung aufgibt (z. B. "Zeig mir die Startseite").
- **Webseite = Gericht**, das der Kellner bringt (z. B. HTML-Datei).

**Ein Webserver:**  
✔ **Empfängt Anfragen** (z. B. "Zeig mir example.com").  
✔ **Sendet Antworten** (z. B. die HTML-Datei der Webseite).  
✔ **Kann verschiedene Inhalte liefern** (HTML, Bilder, Videos, etc.).

---

---

### **2. Apache vs. Nginx – was ist der Unterschied?**


| **Webserver** | **Vorteile**                                                     | **Nachteile**                                     | **Für wen?**                             |
| ------------- | ---------------------------------------------------------------- | ------------------------------------------------- | ---------------------------------------- |
| **Apache**    | Einfach zu konfigurieren, viele Module, gut für Anfänger.        | Langsamer bei vielen gleichzeitigen Verbindungen. | Anfänger, kleine bis mittlere Webseiten. |
| **Nginx**     | Sehr schnell, gut für viele Besucher, wenig Ressourcenverbrauch. | Komplexere Konfiguration.                         | Große Webseiten, Hochverkehrs-Seiten.    |


**Merksatz:**

- **Apache** = Wie ein **Alleskönner-Kellner** (einfach, aber nicht der schnellste).
- **Nginx** = Wie ein **Rennfahrer-Kellner** (schnell, aber braucht mehr Übung).

---

---

### **3. Wichtige Begriffe**


| **Begriff**      | **Erklärung**                                | **Beispiel**                                        |
| ---------------- | -------------------------------------------- | --------------------------------------------------- |
| **HTTP/HTTPS**   | Protokoll für die Übertragung von Webseiten. | `http://example.com` oder `https://example.com`     |
| **Port 80**      | Standard-Port für HTTP.                      | Webseiten ohne Verschlüsselung.                     |
| **Port 443**     | Standard-Port für HTTPS (verschlüsselt).     | Sichere Webseiten (z. B. Online-Banking).           |
| **Virtual Host** | Mehrere Webseiten auf einem Server.          | `website1.com` und `website2.com` auf einem Server. |
| **HTML**         | Sprache für Webseiten.                       | `<html><body>Hallo Welt!</body></html>`             |


---

---

### **4. Wie funktioniert eine Webseite?**

1. Du gibst eine **URL** ein (z. B. `https://example.com`).
2. Dein Browser sendet eine **HTTP-Anfrage** an den Webserver.
3. Der Webserver sucht die **HTML-Datei** (z. B. `index.html`).
4. Der Webserver sendet die **HTML-Datei** zurück an deinen Browser.
5. Dein Browser zeigt die **Webseite** an.

## **🎮 Praxis – Apache installieren und einrichten**

---

---

### **📌 Schritt 1: Apache installieren**

```bash
# Apache installieren
sudo apt update
sudo apt install apache2 -y

# Apache starten
sudo systemctl start apache2

# Apache aktivieren (damit er beim Start des Systems automatisch startet)
sudo systemctl enable apache2

# Status prüfen
sudo systemctl status apache2
```

**Erwartete Ausgabe:**

```
● apache2.service - The Apache HTTP Server
   Loaded: loaded (/lib/systemd/system/apache2.service; enabled; vendor preset: enabled)
   Active: active (running) since ...
```

→ Apache läuft!

---

---

### **📌 Schritt 2: Testseite anzeigen**

1. Öffne einen **Browser** auf deinem Host-PC.
2. Gib die **IP-Adresse deiner VM** ein (z. B. `http://192.168.1.100`).
  - **Falls du in der VM selbst testest:** `http://localhost`

**Erwartet:**

- Du siehst die **Apache-Standardseite** ("It works!").

---

---

### **📌 Schritt 3: Eigene Webseite erstellen**

1. Erstelle eine **HTML-Datei**:
  ```bash
   sudo nano /var/www/html/index.html
  ```
2. Füge folgenden Code ein:
  ```html
   <!DOCTYPE html>
   <html>
   <head>
       <title>Meine erste Webseite</title>
   </head>
   <body>
       <h1>Hallo Welt!</h1>
       <p>Das ist meine erste Webseite auf Apache.</p>
   </body>
   </html>
  ```
3. Speichern: `Strg + O` → `Enter` → `Strg + X`.
4. **Webseite neu laden** im Browser.

**Erwartet:**

- Du siehst **"Hallo Welt!"** und deinen Text.

---

---

### **📌 Schritt 4: Ports und Firewall**

Falls deine Webseite **nicht angezeigt wird**, prüfe die Firewall:

```bash
# Port 80 (HTTP) in der Firewall erlauben
sudo ufw allow 80

# Status prüfen
sudo ufw status
```

**Erwartet:**

```
Status: active
To                         Action      From
--                         ------      ----
80/tcp                     ALLOW       Anywhere
```

### **📝 Aufgabe 5: Virtual Hosts mit Apache einrichten**

**Beschreibung:**

1. Erstelle **zwei Verzeichnisse** für zwei Webseiten:
  ```bash
   sudo mkdir -p /var/www/site1
   sudo mkdir -p /var/www/site2
  ```
2. Erstelle in jedem Verzeichnis eine `**index.html**` mit unterschiedlichem Inhalt.
3. Richte **Virtual Hosts** ein:
  ```bash
   sudo nano /etc/apache2/sites-available/site1.conf
  ```
   Füge folgenden Inhalt ein (ersetze `DEINE_VM_IP` mit der IP deiner VM):
4. Wiederhole das für `site2.conf` (mit `/var/www/site2`).
5. Aktiviere die Sites und starte Apache neu:
  ```bash
   sudo a2ensite site1.conf
   sudo a2ensite site2.conf
   sudo systemctl restart apache2
  ```
6. Teste die Seiten, indem du die **IP deiner VM** im Browser aufrufst und die `Hosts`-Datei auf deinem PC anpasst (oder nutze `curl`):
  ```bash
   curl -H "Host: site1.test" http://DEINE_VM_IP
   curl -H "Host: site2.test" http://DEINE_VM_IP
  ```

**Frage:** Was siehst du, wenn du `site1.test` und `site2.test` aufrufst?

??? success "Lösung:"

    
    **Erwartet:**

    - Wenn du `site1.test` aufrufst, siehst du den **Inhalt von `/var/www/site1/index.html`**.
    - Wenn du `site2.test` aufrufst, siehst du den **Inhalt von `/var/www/site2/index.html`**.

    **Hinweis:**

    - Auf deinem **Host-PC** musst du die `Hosts`-Datei anpassen (z. B. `C:\Windows\System32\drivers\etc\hosts` oder `/etc/hosts` auf Linux/macOS):
    ```
    DEINE_VM_IP site1.test
    DEINE_VM_IP site2.test
    ```
    - Oder nutze `curl` wie oben beschrieben.

### **📝 Aufgabe 6: HTTPS mit Let’s Encrypt einrichten (optional für Fortgeschrittene)**

**Beschreibung:**

1. Installiere **Certbot** (für Let’s Encrypt):
  ```bash
   sudo apt install certbot python3-certbot-apache -y
  ```
2. Richte eine **Domain** ein (z. B. mit einem kostenlosen Dienst wie `duckdns.org`).
3. Führe Certbot aus:
  ```bash
   sudo certbot --apache -d deine-domain.de
  ```
4. Folge den Anweisungen.

**Frage:** Was passiert, wenn du jetzt `https://deine-domain.de` aufrufst?

??? success "Lösung:"

    
    **Erwartet:**

    - Deine Webseite wird **verschlüsselt** angezeigt (mit einem **grünen Schloss** im Browser).
    - Certbot hat automatisch ein **SSL-Zertifikat** erstellt und Apache konfiguriert.
