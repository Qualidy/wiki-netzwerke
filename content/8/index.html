    🔍 Tag 8: Monitoring & Fehlerbehebung - Einfach erklärt¶

    📚 Theorie – ganz einfach erklärt¶

    1. Warum Monitoring?¶

    Stell dir vor, du hast ein Auto:

    • Ohne Monitoring: Du fährst einfach los und hoffst, dass nichts kaputt geht.
    • Mit Monitoring: Du hast ein Armaturenbrett, das dir zeigt, ob alles in Ordnung ist (z. B. Ölstand, Temperatur).

    Monitoring im Netzwerk:
    ✔ Überwacht den Datenverkehr (wer sendet was?).
    ✔ Erkennt Probleme frühzeitig (z. B. zu viele Anfragen an einen Server).
    ✔ Hilft bei der Fehlerbehebung (z. B. warum ist die Webseite langsam?).

    2. Wichtige Tools für Monitoring¶

    Tool Wofür? Beispielbefehl
    **ping** Prüft, ob ein Gerät erreichbar ist. ping 8.8.8.8
    **traceroute** Zeigt den Weg eines Pakets durchs Netzwerk. traceroute google.com
    **netstat** Zeigt aktive Netzwerkverbindungen. netstat -tuln
    **ss** Moderner Ersatz für netstat. ss -tuln
    **iftop** Zeigt den aktuellen Datenverkehr an. sudo iftop
    **nload** Zeigt die Auslastung der Netzwerkinterfaces. nload
    Wireshark Analysiert den Datenverkehr im Detail. sudo wireshark

    3. Wichtige Begriffe¶

    Begriff Erklärung Beispiel
    Paket Ein kleines Datenstück, das durchs Netzwerk geschickt wird. Wie ein Brief im Postsystem.
    Latenz Die Zeit, die ein Paket braucht, um von A nach B zu kommen. "Ping-Zeit" in Millisekunden.
    Bandbreite Wie viel Daten pro Sekunde übertragen werden können. 100 Mbit/s.
    Timeout Wenn eine Anfrage zu lange auf eine Antwort wartet. ping: timeout
    Log-Datei Eine Datei, in der Ereignisse protokolliert werden. /var/log/syslog

    4. Fehlerbehebung – Schritt für Schritt¶

    1. Problem erkennen (z. B. "Die Webseite lädt nicht").
    2. Symptome sammeln (z. B. "Fehlermeldung: Connection refused").
    3. Mögliche Ursachen prüfen (z. B. Server ausgefallen, Firewall blockiert Port).
    4. Tests durchführen (z. B. ping, traceroute, Logs prüfen).
    5. Lösung umsetzen (z. B. Server neu starten, Firewall-Regel anpassen).

    🎮 Praxis – Monitoring-Tools verwenden¶

    📌 Schritt 1: ping – Prüfen, ob ein Gerät erreichbar ist¶

    1
2
3
4
5
    # Prüfe, ob Google erreichbar ist
ping 8.8.8.8

# Prüfe, ob ein Gerät in deinem Netzwerk erreichbar ist
ping 192.168.1.1

    Erwartete Ausgabe:

    1
2
    PING 8.8.8.8 (8.8.8.8) 56(84) bytes of data.
64 bytes from 8.8.8.8: icmp_seq=1 ttl=117 time=12.3 ms
    • **time=12.3 ms** = Latenz (je kleiner, desto besser).
    • **ttl=117** = Time to Live (wie oft das Paket weitergeleitet werden darf).

    Abbruch: Strg + C

    📌 Schritt 2: traceroute – Den Weg eines Pakets verfolgen¶

    1
2
    # Zeige den Weg zu Google
traceroute google.com

    Erwartete Ausgabe:

    1
2
3
4
     1  192.168.1.1  1.2 ms
 2  10.0.0.1    5.6 ms
 3  216.239.40.123  12.3 ms
 ...
    • Jede Zeile = ein Hop (ein Router auf dem Weg).
    • **ms** = Zeit, die das Paket für diesen Hop braucht.

    📌 Schritt 3: netstat oder ss – Aktive Verbindungen anzeigen¶

    1
2
3
4
5
    # Zeige alle aktiven TCP- und UDP-Verbindungen
netstat -tuln

# oder (modernere Alternative)
ss -tuln

    Erwartete Ausgabe:

    1
2
3
    Proto Recv-Q Send-Q Local Address           Foreign Address         State
tcp        0      0 0.0.0.0:22              0.0.0.0:*               LISTEN
tcp        0      0 192.168.1.100:80       0.0.0.0:*               LISTEN
    • **LISTEN** = Der Server wartet auf Verbindungen (z. B. Port 22 = SSH, Port 80 = HTTP).
    • **ESTABLISHED** = Eine aktive Verbindung.

    📌 Schritt 6: Wireshark – Datenverkehr analysieren¶

    1
2
3
4
5
    # Installiere Wireshark
sudo apt install wireshark -y

# Starte Wireshark (als Root)
sudo wireshark

    Was du siehst:

    • Eine Liste aller Pakete, die durch dein Netzwerk fließen.
    • Farben:
    • Blau = TCP
    • Grün = HTTP
    • Schwarz = ICMP (z. B. Ping)
    • Rot = Fehler

    Filter:

    • Gib oben in der Leiste z. B. http ein, um nur HTTP-Pakete anzuzeigen.
    • Oder ip.addr == 8.8.8.8, um nur Pakete von/to 8.8.8.8 anzuzeigen.

    📌 Schritt 7: Log-Dateien lesen¶

    1
2
3
4
5
    # Zeige die letzten Einträge der System-Logs
tail -f /var/log/syslog

# Zeige die Apache-Logs (falls Apache installiert ist)
tail -f /var/log/apache2/access.log

    Wichtige Log-Dateien:

    Datei Inhalt
    /var/log/syslog Systemweite Logs (z. B. Netzwerkfehler).
    /var/log/auth.log Anmeldungen (z. B. SSH-Logins).
    /var/log/apache2/access.log Zugriffe auf den Apache-Webserver.
    /var/log/mail.log E-Mail-Logs (z. B. Postfix).

    Beenden: Strg + C

    💡 Übungen – einfach & praxisnah¶

    📝 Aufgabe 1: ping testen¶

    Beschreibung:

    1. Pinge die IP 8.8.8.8 (Google DNS).
    2. Pinge die IP 192.168.1.1 (dein Router, falls du im Netzwerk bist).
    3. Pinge eine nicht existierende IP (z. B. 192.168.1.255).

    Fragen:

    1. Was ist der Unterschied zwischen den Ausgaben?
    2. Was bedeutet Destination Host Unreachable?
    Lösung:

    Befehle: 

    1
2
3
    ping 8.8.8.8
ping 192.168.1.1
ping 192.168.1.255

    1. Unterschiede:

    • 8.8.8.8 und 192.168.1.1: Antworten mit 64 bytes from ... (erreichbar).
    • 192.168.1.255: Keine Antwort, stattdessen Destination Host Unreachable (nicht erreichbar).

    2. Destination Host Unreachable:

    • Das bedeutet, dass das Ziel nicht erreichbar ist (z. B. weil die IP nicht existiert oder das Gerät ausgeschaltet ist).

    📝 Aufgabe 2: traceroute ausprobieren¶

    Beschreibung:

    1. Führe traceroute google.com aus.
    2. Führe traceroute 8.8.8.8 aus.

    Frage: Warum sehen die Wege unterschiedlich aus?

    Lösung:

    Befehle: 

    1
2
    traceroute google.com
traceroute 8.8.8.8

    Warum unterschiedlich?

    • google.com wird zuerst in eine IP-Adresse umgewandelt (z. B. 142.250.186.46).
    • 8.8.8.8 ist bereits eine IP-Adresse.
    • Der Weg kann sich unterscheiden, weil:
    • Google nutzt Content Delivery Networks (CDN), die den schnellsten Weg wählen.
    • 8.8.8.8 ist ein DNS-Server von Google, der direkt angesprochen wird.

    📝 Aufgabe 3: Aktive Verbindungen prüfen¶

    Beschreibung:

    1. Zeige alle aktiven Verbindungen mit ss -tuln an.
    2. Starte einen Webserver (z. B. Apache) und prüfe erneut.

    Frage: Welcher Port wird für HTTP verwendet?

    Lösung:

    Befehle: 

    1
    ss -tuln
    Nach dem Starten von Apache: 
    1
2
    sudo systemctl start apache2
ss -tuln

    Erwartete Ausgabe (Ausschnitt): 

    1
    tcp   LISTEN  0  128  0.0.0.0:80  0.0.0.0:*
    Port für HTTP: - Port 80.

    📝 Aufgabe 4: Datenverkehr mit iftop beobachten¶

    Beschreibung:

    1. Installiere iftop und starte es.
    2. Lade eine große Datei herunter (z. B. wget https://releases.ubuntu.com/26.04/ubuntu-26.04-desktop-amd64.iso).
    3. Beobachte den Datenverkehr in iftop.

    Frage: Was siehst du in iftop?

    Lösung:

    Befehle: 

    1
2
    sudo apt install iftop -y
sudo iftop
    In einem anderen Terminal: 
    1
    wget https://releases.ubuntu.com/26.04/ubuntu-26.04-desktop-amd64.iso

    Erwartete Ausgabe in iftop:

    • Eine Liste der Verbindungen mit:
    • Quell-IP und Ziel-IP.
    • Datenmenge (z. B. 1.5MB).
    • Geschwindigkeit (z. B. 100KB/s).

    📝 Aufgabe 6: Wireshark – HTTP-Traffic analysieren¶

    Beschreibung:

    1. Installiere Wireshark und starte es.
    2. Starte eine Aufzeichnung auf deinem Netzwerkinterface (z. B. eth0).
    3. Rufe eine Webseite im Browser auf (z. B. http://example.com).
    4. Stoppe die Aufzeichnung und filtere nach HTTP.

    Frage: Welche Informationen siehst du in den HTTP-Paketen?

    Lösung:

    Befehle: 

    1
2
    sudo apt install wireshark -y
sudo wireshark
    Schritte in Wireshark:

    1. Wähle das Netzwerkinterface (z. B. eth0).
    2. Klicke auf den blauen Hai (Start).
    3. Rufe http://example.com im Browser auf.
    4. Stoppe die Aufzeichnung (rotes Quadrat).
    5. Gib im Filterfeld http ein.

    Erwartete Informationen in HTTP-Paketen:

    • GET / HTTP/1.1 = Anfrage an den Server.
    • Host: example.com = Die angefragte Webseite.
    • HTTP/1.1 200 OK = Antwort des Servers (200 = Erfolg).
    • Content-Type: text/html = Typ der Antwort (HTML-Seite).

    📝 Aufgabe 7: Fehlerbehebung – Webserver lädt nicht¶

    Beschreibung:
    Problem: Dein Apache-Webserver lädt keine Seiten mehr.

    Schritte zur Fehlerbehebung:

    1. Prüfe, ob Apache läuft: 
      1
       sudo systemctl status apache2
    2. Prüfe die Logs: 
      1
       tail -f /var/log/apache2/error.log
    3. Prüfe, ob Port 80 offen ist: 
      1
       ss -tuln | grep 80
    4. Prüfe die Firewall: 
      1
       sudo ufw status

    Frage: Welche möglichen Ursachen könnte es geben?

    Lösung:

    Mögliche Ursachen:

    1. Apache läuft nicht:
      • Lösung: sudo systemctl start apache2
    2. Fehler in der Konfiguration:
      • Lösung: Prüfe /var/log/apache2/error.log und korrigiere die Konfiguration.
    3. Port 80 ist blockiert:
      • Lösung: sudo ufw allow 80
    4. Apache bindet nicht an Port 80:
      • Lösung: Prüfe /etc/apache2/ports.conf und starte Apache neu: sudo systemctl restart apache2
